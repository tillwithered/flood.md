# Адаптер автоматизации Jev

Jev — движок решений по умолчанию в новых настройках фоновой автоматизации flood.md. Он остаётся опциональным: не заменяет встроенный MCP-сервер, требует явно сохранённый ключ до включения автоматизации и никогда не выбирается провайдером `Авто`. При обновлении явно выбранный ранее провайдер сохраняется.

## Два независимых контура

- Внешние агенты используют локальный MCP-сервер flood.md: получают рабочий контекст проекта и выполняют изменения через проверки политик.
- Фоновый мост desktop-приложения использует один явно выбранный движок: локальный Codex, Claude Code или Gemini CLI либо Jev.

Отключение Jev, удаление ключа или отсутствие сети не мешает MCP и ручной работе с задачами.

## Подключение

1. Откройте **Настройки → MCP и AI**.
2. Сохраните API-ключ Jev. flood.md хранит его в системном хранилище учётных данных, а не в Markdown, файлах проекта, логах или frontend-бандле.
3. Выберите **Jev** как провайдер автоматизации.
4. Включите фоновую обработку сигналов.

Только для разработки поддерживаются `TYPESAFE_API_KEY`, `TYPESAFE_BASE_URL` и `TYPESAFE_DEFAULT_MODEL`. Сохранённый ключ имеет приоритет над переменной окружения. Адрес по умолчанию — `https://api.typesafe.ai/v1/systemone`, модель — `jev-latest`.

## Контракт решения

flood.md передаёт ограниченный контекст проекта, до десяти сводок открытых задач и пакет захваченных Telegram-сигналов. Jev отвечает на типизированные вопросы выбора:

- действие: создать, обновить, отметить дублем, пропустить или запросить данные;
- срочность: обычная, важная или срочная;
- необязательная связанная открытая задача.

Jev не пишет файлы, не вызывает MCP-инструменты, не выполняет инструкции из сообщений и не формирует произвольные мутации. flood.md детерминированно собирает поля задачи и применяет результат через то же хранилище и те же политики, что и локальная автоматизация. Уверенность в действии ниже `0.78`, отсутствующая ссылка на связанную задачу и противоречивые ответы превращаются в видимый вопрос пользователю, а не в скрытое изменение.

## Приватность и ошибки

- Jev работает в облаке и подключается только явно; интерфейс показывает эту границу до выбора.
- `Авто` остаётся локальным и не может незаметно переключиться на Jev.
- Запрос ограничен 15 секундами и не повторяется адаптером, чтобы не создавать скрытый расход.
- Ключ по конструкции не попадает в состояние запроса.
- Ошибки API, авторизации, схемы и сети оставляют события восстанавливаемыми в очереди автоматизации.
- Модель ответа и расход токенов остаются в результате запуска для диагностики; ключ никогда не сохраняется.

Сетевой контракт соответствует официальному SDK TypeSafe AI: авторизованный Bearer-токеном `POST /v1/systemone` с полями `state`, именованными `questions` и `model`.
