# Геометрия: отношения, плотность, углы

[Индекс](README.md) · детализация foundations 0.2. Ни один размер здесь не оправдывает потерю текста или доступного действия.

## 1. Пространство описывает связь

Не распределять одинаковые 16 px между каждым div. Сначала назвать отношения: часть control, составной объект, группа, секция, регион. Не каждый DOM wrapper — самостоятельный смысловой уровень.

| Отношение | Рабочая шкала | Пример |
| --- | --- | --- |
| Внутри control | 4–8 | Glyph/label, leading/trailing indicator |
| Между частями construct | 12–16 | Поля одной формы, title/body/action |
| Между связанными constructs | 24 | Поиск и список результатов |
| Между sections | 32 | Данные проекта и интеграции |
| Между regions | 48, иногда 64 | Индекс и самостоятельная рабочая область |

Использовать текущие semantic space tokens 8/16/24/32/48. Дополнительные 4/12 — базовая шкала, не новые смысловые роли. Border 1 px, оптические поправки и связанный radius не обязаны кратно делиться на четыре.

Один parent управляет gap между peers. Child не добавляет внешний margin, который вместе с gap создаёт непредсказуемые 40 px. Внутренние связи обычно теснее внешних; исключение обосновывается отношением, а не «так красивее».

## 2. Практические recipes

**Поле:** label → input 8; input → helper/error 4–8; между соседними field groups 16; перед новым смысловым разделом 24–32. Error заменяет/дополняет helper рядом с полем и не отрывается большим section gap.

**Dialog:** общий content inset 24 на обычном окне, 16 на узком. Header, body и footer держат одну ось. Между title и subtitle 4–8; body отделяется 16–24. Border header/footer только по [контракту материалов](materials-and-borders.md), не по привычке.

**Dense collection:** min row height 36–40 для одной строки; 48–56 при полезной второй строке. Это кандидаты для новых компонентов, не запрет существующих размеров. Межстрочный gap 0–4 у единой collection; standalone actions — 8–12. Не менять плотность списка при hover.

**Settings:** max reading/settings width из существующих tokens; label и control образуют одну строку, пока помещаются. При нехватке места control переносится под label, а не выталкивает его за край. Секции разделены 32, связанные rows — компактнее.

**GitHub picker:** header с project/account; затем search; затем компактная строка filters; затем список; затем sticky commit zone. Шапка и footer не входят в прокручиваемый список. Owner/name и метаданные выровнены по общей оси; фильтры не превращаются в равнозначный главному действию ряд крупных кнопок.

Числа — стартовая геометрия; длинный RU текст имеет приоритет над фиксированной высотой. Вводить отдельные density modes только при реальной потребности, не как новый preference ради одного экрана.

## 3. Ширина важнее количества колонок

Использовать `--page-gutter`, `--content-reading`, `--content-settings`, `--content-wide`. Не растягивать редактор текста на всю доступную ширину и не центрировать каждый отдельный блок на своей оси.

Сначала уменьшать внешнее пространство и скрывать необязательную метаинформацию, затем перестраивать layout. Не сжимать текст до 11 px и targets до размера glyph. При невозможности master/detail — одна рабочая панель с явным Back и сохранением позиции списка.

Начальные точки проверки: доступная content width около 640/960/1280 px плюс реальное минимальное Tauri-окно. Это тестовые ширины, не «магические breakpoints». Breakpoint выбирается по моменту реального переполнения сценария.

## 4. Размер control не равен размеру иконки

Базовые кандидаты: height 32 compact, 36 default, 40 prominent. Glyph 16/18/20 живёт внутри target, а не задаёт target. Существующий 34 px icon-button не переименовывать массово ради круглого числа.

Для coarse pointer ориентир 44 px. Для desktop следить за hit target и расстояниями, не только видимой иконкой. Native controls, zoom, focus и длинные labels проверяются вместе. Accessible name обязателен для icon-only action; tooltip не заменяет имя.

## 5. Радиусы — по роли, не по количеству пикселей

| Роль | Базовое предложение |
| --- | --- |
| Прямой внешний AppShell | Без дополнительного скругления |
| Compact control | 8 px |
| Default control / самостоятельная row | 10 px |
| Panel / dialog | 16 px |
| Круглый avatar / специализированный chip | Отдельный shape contract |

Не делать radius 24–32 у каждого поля ради «мягкости». Мягкость создают и edge contrast, и материал, и spacing. В маленьком control слишком большой radius создаёт незапланированный pill. При добавлении компонента использовать semantic role, не новый локальный 11/13/17 px.

## 6. Вложенные радиусы считаются от видимых контуров

Для параллельных rounded rectangles: `inner = max(0, outer − visible inset)`.

Пример: внешний border-box radius 16; border 1 + padding 5 дают расстояние до внутреннего border-box 6; внутренний radius 10. Если padding равен 6 при том же border, inset уже 7, а связанный radius — 9. Не вычитать padding механически.

В [CSS-образце](recipes/materials.css) `.compound` хранит `--material-radius` и `--visible-inset`; padding и inner radius вычисляются из них. Если наружный видимый edge — outline/spread shadow, сначала уточнить, от какого контура измеряется inset. Нельзя смешивать content-box и border-box геометрию.

Это правило не применяется к кругам, pills, blob assets, непараллельным контурам и произвольным squircles. `corner-shape` — progressive enhancement; border-radius fallback полноценный. Не объявлять `outer − inset` математически точным offset для любой superellipse.

## 7. Оптика и стабильность

Иконка центрируется по смысловому силуэту и baseline соседнего текста; допустима маленькая зафиксированная оптическая поправка, если без неё форма выглядит смещённой. Она не заменяет правильную box model.

Border width и padding не меняются на hover/selected/error. Reserve 1 px transparent border, когда состояние требует видимого border. Outline не участвует в layout. Loading indicator занимает зарезервированное место, не двигает label.

1 CSS px не всегда один физический пиксель; проверять разные DPR. Не использовать scale(.5) на интерактивной поверхности ради hairline. Заметные стыки лучше выровнять и убрать дубли, чем лечить размытие ещё одной shadow.

## 8. Проверка

На одном заполненном экране назвать три масштаба расстояний: control, group, section. Проверить общую ось header/body/footer, перенос длинных названий и min-width:0 у flex/grid children. У compound surface измерить реальный inset, не оценивать на глаз.

Состояния rest/hover/focus/selected/invalid не двигают геометрию. У узкого layout и 200% text zoom остаются подписи и actions. Числа и shape проверяются вместе с [материалами](materials-and-borders.md), а не как самостоятельная таблица красивых токенов.
