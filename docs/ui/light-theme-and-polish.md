# Светлая тема и точность деталей

[Индекс](README.md) · clean-light 0.3.1 · 2026-09-19 · [образец](recipes/polish.html).

**Статус: направление светлого образца одобрено владельцем.** Это не утверждение о внедрении в App.svelte. Тёмная палитра и Warning/Danger/Success сохранены. Контракты ниже уточняют прежние foundations; новый эксперимент не отменяет принятую основу.

## 1. Чистый фон, локальная различимость

В 0.2 фон #f4f4f2 и Quiet #f7f7f7 давали около 1.028:1; secondary control сливался с такой же заливкой панели. Затем canvas #e9e9e6 отделил белые карточки, но владелец отверг тёплый серый фон как грязный. Не возвращать этот вариант под видом улучшенного контраста.

**Не делать темнее весь экран ради границы одного компонента.** Проверять actual parent, локальный край и собственную заливку control. Не усиливать глобальный --line ради одной поверхности.

| Роль светлого образца | Значение | Применение |
| --- | --- | --- |
| Canvas | #fafafa | Почти белая нейтральная среда |
| Panel | #ffffff | У самостоятельного Quiet на близком фоне локальный край #e8e8e8, без тени |
| Внутренняя группа | #f5f5f5 | Локальная подложка, не ковёр всей страницы |
| Secondary control | #f2f2f2 | Собственная заливка и край #d9d9d9 |
| Control hover / pressed | #e9e9e9 / #dfdfdf | Обратная связь без скачка геометрии |
| Field | #ffffff | Отдельная необходимая граница #858585 |
| Row hover / selected | #f7f7f7 / #f1f1f1 | Выбор дополнительно выражен состоянием и меткой |
| Muted text | #555555 | Нейтральный, без общей opacity контейнера |

Порог card/canvas >=1.20 из 0.3 удалён: он подталкивал затемнять фон ради одной цифры. Декоративную иерархию оцениваем на полном экране; функциональный контраст не ослабляем. Не назначать один surface карточке, control и вложенной группе. Не превращать каждый раздел документа в карточку ради этого рецепта.

[W3C: non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) различает декоративные границы и информацию, необходимую для распознавания controls/состояний. Фокус и необходимые границы не обязаны быть такими же бледными, как край панели.

## 2. Темы по ролям, не инверсией

Светлая: почти белый canvas, белая рабочая поверхность, нейтральный control и локальный край. Тёмная: существующая база, отдельный тон вложенных controls; вклад edge/верхнего света может быть больше. Белый блик на белой панели может почти исчезнуть — не делать его ярче любой ценой.

При смене темы связанные foreground/background меняются вместе. Не анимировать старую заливку под уже новым текстом. В образце transitions кратко выключены при смене палитры. Forced colors сохраняет пользовательскую system palette, даже если её Highlight синий.

## 3. Текст вместо коробок

Название — главный объект, контекст — вторичный уровень, состояние — отдельное значение. Сохранять шкалу body 14/20, compact 13/18, section 20/26, page 24/32. Стартовые веса: 500 название, 400 контекст, 600 секция; не менять массово существующие 650 без аудита.

Не компенсировать шум шрифтом 11 px, сверхтонким начертанием, капсом всех labels или opacity родителя. Длинное название переносится; min-height не является потолком. Ellipsis в индексе требует доступного полного имени без зависимости только от hover. Не обрезать одновременно owner и repository.

## 4. Метаданные не требуют badges

Дата, repository, provider и число источников обычно остаются текстом. Badge нужен для категории/фильтра/значимого состояния, не для каждого поля JSON. Общую информацию можно вынести в заголовок при однозначном scope, но нельзя удалять provenance, ownership, permissions, blocker или неизвестное состояние.

A/B сохраняет все значения дословно и читает один массив данных. Даты и счётчики имеют устойчивую колонку и tabular numerals. Относительное время не заменяет точное время в истории значимых действий.

## 5. Оси и оптическая точность

Заголовок, поле, текст строки и footer держат общую content axis. Secondary line начинается под названием, не под значком. Значок имеет стабильный slot; измеренная поправка около 1 px допустима внутри slot, не transform всей кнопки. Использовать существующий набор иконок, не добавлять glyph каждому helper.

У расстояния один владелец: parent gap вместо суммы детских margins. Сначала исправить необоснованные разные x-координаты и вложенные интервалы, потом shadow/radius. [Геометрия](geometry.md).

## 6. Состояния и устойчивая геометрия

- Rest сообщает доступное действие; hover не единственное доказательство интерактивности.
- Hover локален и не равен selected.
- Selected переживает уход курсора и имеет правильную семантику/метку.
- Focus-visible независим, различим на selected и invalid.
- Pending сохраняет место label/индикатора; success только после подтверждения.
- Disabled не требует пунктирной рамки: не смешивать disabled, drop target и draft.

Не менять border width, font-weight, padding и расположение actions на hover. Действия по наведению доступны также через focus-within/touch; Save, Stop, permissions и error recovery не бывают hover-only.

Проверять semantic текст на panel, hover и selected, а не только на розовой/жёлтой плашке. Текущий selected #f1f1f1 заменяет #ecece8 прошлого пилота; существующее семейство статусов сохраняется.

## 7. Микроповедение

Фильтр не теряет выбранный объект. Summary показывает скрытый выбор; commit относится к выбранной сущности, не первому видимому результату. Empty collection, no results и loading failure — разные состояния.

Результат находится рядом с действием. Не дублировать один успех banner + toast + badge. Длительная проблема остаётся до исправления. Не задерживать готовые данные ради анимации; skeleton повторяет геометрию. Не заменять каждый spinner блобом. [Поведение](interaction.md).

## 8. Проверка и перенос

A/B использует те же объекты, текст, порядок, размеры и состояние. Найти главный объект, действие, выбранную строку и ошибку без движения курсора; затем пройти Tab. Проверить light/dark, narrow, длинный RU, масштабирование текста, поля и focus. Blur/grayscale не являются тестом доступности.

[polish.html](recipes/polish.html) — изолированный образец. materials.html/materials.css остаются baseline 0.2. Приложение не импортирует demo CSS. При внедрении согласованно перенести нужные роли в единственный production token source, без цепочки overrides.

[Проверки](recipes/polish-checks.md); [общая приёмка](acceptance.md). Одобрение внешнего вида не заменяет проверки реального Tauri flow.
