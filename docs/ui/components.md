# Компонентные контракты

[Индекс](README.md) · геометрия и роли берутся из [foundations](foundations.md), поведение — из [interaction](interaction.md).

Контракт описывает назначение, анатомию, состояния и ограничения. Одинаковая rounded rectangle ещё не делает два компонента взаимозаменяемыми.

## Выбор поверхности

| Намерение | Поверхность | Почему не соседний паттерн |
| --- | --- | --- |
| Постоянно работать с объектом, возвращаться к нему | Page / рабочая область | Modal мешает длительной навигации |
| Просматривать соседние объекты, сохраняя список | Detail pane / drawer | Новый modal на каждый объект ломает triage |
| Закончить ограниченную операцию с контекстом и подтверждением | Modal | Popover тесен для сравнения и последствий |
| Изменить одно простое значение | Select / combobox | Отдельный диалог создаёт лишний шаг |
| Выполнить локальную команду | Menu | Это не выбор значения поля |
| Узнать короткую необязательную деталь | Disclosure / popover | Не нужно отдельное рабочее пространство |
| Сравнивать много объектов по одинаковым полям | Table / плотный list | Стопка карточек разрушает сравнение |

Число вариантов не является жёстким законом «после семи — modal». Editable combobox может корректно искать в большом наборе. Решение зависит от сложности строки, фильтров, прав, preview, commit и контекста. [WAI-ARIA combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).

## Actions

**Button.** Видимый label называет результат: «Подключить репозиторий», «Сохранить правило». В области одного решения — одно визуально доминирующее действие, но не обязательно одна кнопка на весь экран. Secondary не конкурирует с primary; tertiary не теряет hit area. Не заменять текст иконкой, если смысл неоднозначен. Pending сохраняет label и ширину. Disabled имеет доступную причину рядом, не только tooltip. Destructive отделён пространством и подтверждением со scope.

**Icon button.** Настоящий button, доступное имя, видимый focus. Tooltip — дополнение, не единственная инструкция. Иконка 16–20 px живёт внутри target, не определяет размер target. У touch/keyboard остаётся тот же путь к действию.

**Link.** Использовать для навигации, button — для изменения состояния/операции. Внешний адрес в Tauri проходит существующий безопасный opener. Не делать открытие URL побочным эффектом выбора radio.

## Ввод и выбор

**Text field.** Label, value, optional hint/error; placeholder не заменяет label. Ошибка привязана к полю. Один trailing action, например clear, не два перекрывающихся controls. Password/token не попадает в tooltip/log. Input сохраняет focus и value во время обновления данных.

**Textarea/editor.** Enter создаёт новую строку. Отдельное сохранение или autosave обозначено явно; режимы не смешиваются. Formatting toolbar обслуживает editor, а не становится вторым главным header. Markdown preview безопасно обрабатывает недоверенный контент. Отдельные pending/error/conflict состояния; при конфликте draft сохраняется.

**Checkbox.** Независимое включение или multiple selection. **Radio.** Один выбор из группы; выбор может оставаться draft до общего commit. **Switch.** Немедленное устойчивое on/off изменение, только если его действительно можно выполнить сейчас; ошибка возвращает достоверное состояние. Не использовать switch для запуска одноразового задания.

**Select.** Короткое поле с простыми взаимоисключающими значениями. **Combobox.** То же намерение, но нужен текстовый поиск. Семантика значения и keyboard behavior соответствуют выбранному паттерну. Не собирать combobox из `role=menu` и произвольных tabbable controls внутри option.

**Menu.** Команды текущего объекта, группировка по смыслу, destructive в конце отдельной группы. Открытие, перемещение, выбор, Escape и возврат focus предсказуемы. Не размещать внутри menu editor, длинное объяснение permissions или многошаговое подключение.

**Filter.** Меняет представление, не данные. Активное условие видно после закрытия меню. Есть reset; query и filters вместе определяют empty result. Не путать «нет совпадений» с «нет объектов в проекте».

## Коллекции и структура

**Standalone action row.** Самостоятельный переход/настройка: устойчивый radius 8–10, padding 8–12, gap между соседями 8–12. Identity, краткая secondary line, trailing affordance. Hover внутри контура. Disclosure остаётся внутри той же поверхности. Не склеивать независимые действия постоянными разделителями.

**Dense collection row.** Элемент единого списка задач/репозиториев: общий ритм, тонкие разделители или меньший gap, ровные колонки. Строка может содержать ссылку, selection control и отдельное menu; не вкладывать button в button. Не делать каждую task row самостоятельной приподнятой карточкой. Это отдельный контракт, не исключение, которое каждый автор угадывает.

**Table.** Нужна для сопоставления одинаковых полей, сортировки и batch selection; не запрещена только потому, что интерактивна. Заголовки и порядок колонок устойчивы, числа выровнены. На узкой ширине убрать вторичное или перейти к meaningful row; горизонтальная прокрутка таблицы допустима, всей страницы — нет. Не терять сортировку и selection при pagination.

**Card.** Один самостоятельный результат, выбор или status. Header/body/action относятся к одному объекту. Card не является универсальной заменой section. Не вкладывать стопки разных card backgrounds. У status-card count и дочерние строки наследуют материал.

**Tabs.** Переключают равноправные представления одного контекста. Open bar, один нижний divider, neutral rounded active tab, без общей capsule/shadow. Настоящие tabs имеют tablist/tab/tabpanel и соответствующее управление стрелками; если это навигационные ссылки — не имитировать tab semantics. Для дорогой загрузки использовать явную активацию Enter/Space, не запускать запрос на каждое перемещение focus. В narrow layout focus прокручивает активный tab в видимую область.

**Disclosure.** Короткая вторичная деталь существующего объекта. Expanded state читается визуально и через aria-expanded. Полноценный документ, skill, history editor или connection flow не превращать в accordion между строками.

## Временные слои

**Modal.** Один сфокусированный сценарий. Labelled header, ограниченно прокручиваемый body, устойчивый footer действий. `aria-modal` само по себе не создаёт модальность. Проверить initial focus, Tab containment, inert background, Escape, restore focus и отсутствие перекрытого focus. Подробности — [WAI-ARIA dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

Клик по backdrop не должен молча терять введённое. В содержательном редакторе предпочтительны явный Cancel/Close и предупреждение при dirty state. Не закрывать диалог из-за отпускания мыши после выделения текста. Escape сначала закрывает верхний popover, затем диалог; не оба за один event.

**Drawer/detail pane.** Оставляет источник выбора видимым и полезным. Не автоматически modal: если фон остаётся доступен, нет aria-modal и trap. На narrow width становится отдельной рабочей областью или осознанно модальным слоем с соответствующим focus contract. Не превращать в постоянный склад чата, настроек и диагностики одновременно.

**Tooltip.** Только короткое дополнение. Открывается и для focus; не содержит обязательные actions/ошибки или единственное объяснение недоступности. Не закрывает соседний target.

## Обратная связь

**Inline error** — рядом с причиной и восстановлением. **Banner/notice** — длительное состояние области, например нет доступа; исчезает, когда причина устранена. **Toast** — краткий итог завершившейся операции. Важное требование решения не должно исчезать как toast. Undo доступен также из устойчивого места, если потеря toast лишает восстановления.

**Skeleton** — ожидание первой структуры, геометрия близка к результату. **Spinner** — активная операция с неизвестным процентом. **Progress bar** — только измеряемая доля с понятным знаменателем. Не выдавать animation elapsed за реальный прогресс агента.

**Empty state** — что здесь появится и одно релевантное действие; не герой-иллюстрация на полэкрана. Различать first use, empty after filter, permission denied, offline и loading. **Conflict** — текущая версия и локальный draft с безопасным способом сверки; не обычный toast «ошибка».

## Что обязан иметь новый общий компонент

Задокументированные props/events; владелец state; именованные slots/snippets; responsive и keyboard contract; применимые состояния; ссылка на один полный сценарий и его проверки. Не создавать универсальный компонент с десятками флагов до появления второго реального применения.
