# flood.md — дизайн

Локальное десктоп-приложение для личных задач по проектам. Проект можно связать с рабочим чатом. Интерфейс спокойный, компактный и понятный с первого открытия.

## Первая версия

- Полноценное десктоп-приложение, локальное хранение в Markdown и MCP для агента.
- Слева — проекты, в центре — задачи выбранного проекта. Доступен общий список задач.
- Нажатие на задачу раскрывает описание и снимок исходного сообщения.
- Создать, отредактировать и завершить задачу можно без многошаговых форм.
- Telegram — следующая интеграция. До неё проект и снимок сообщения можно добавить вручную или через MCP.
- Опциональное компактное окно flood-buddy — позже.

## Задача

- Описание человеческим языком: что нужно сделать.
- Привязка к проекту.
- Дата постановки, автоматически.
- Срочность: обычная, важная, срочная.
- Состояние: открыта или выполнена.
- Необязательный снимок сообщения: текст, автор, время и ссылка на оригинал, если доступна. Хранится локально и сохраняет контекст независимо от изменений оригинала.

## Навигационная модель

- Чат является проектом и имеет собственную посадочную страницу с полным списком задач.
- Нажатие на название проекта открывает его страницу; отдельная стрелка только раскрывает или сворачивает быстрый список задач в боковой панели.
- Задача открывается как из боковой панели, так и с посадочной страницы. Боковая панель служит быстрым доступом, посадочная — обзором проекта.
- «Все задачи» открывает общую страницу с группировкой открытых задач по проектам и отдельным сворачиваемым списком выполненных.

## Палитра

Основа — чёрный, белый и нейтральные серые. По умолчанию светлая тема. Акценты используются только для состояния и срочности, небольшими метками или иконками.

| Назначение | Цвет |
| --- | --- |
| Основной фон | `#FFFFFF` |
| Вторичная поверхность | `#F5F5F5` |
| Основной текст и основная кнопка | `#171717` |
| Вторичный текст | `#666666` |
| Границы | `#E5E5E5` |
| Обычная срочность / открыта | `#666666` |
| Важная | `#92400E` — янтарный |
| Срочная / ошибка | `#B91C1C` — красный |
| Выполнена / успех | `#166534` — зелёный |

Цвет всегда сопровождается текстом или понятной иконкой. Не заливать строки задач яркими цветами. Основная кнопка чёрная с белым текстом. Фокус клавиатуры — отчётливая контрастная обводка.

## Визуальные правила

- Читаемый системный шрифт; основной текст 14–16 px. Описание задачи — главный визуальный элемент строки.
- Ритм отступов: 4, 8, 12, 16, 24, 32 px. Умеренные скругления 6–10 px.
- Скруглённые поверхности используют corner smoothing в форме squircle/superellipse поверх обычного `border-radius`. Радиус остаётся fallback для WebView без поддержки; настоящие pills и круглые индикаторы не сглаживать в squircle.
- Списки и тонкие разделители вместо множества вложенных карточек.
- Минимум теней. Без градиентов, стекла и декоративных цветных блоков.
- У кнопки не должно быть одновременно фоновой заливки и обводки: использовать только один способ выделения. Вторичные кнопки по умолчанию — на очень светлой нейтрально-серой заливке без рамки.
- Нейтральные серые не должны иметь заметного синего, зелёного, жёлтого или бежевого подтона.
- Даты и источник вторичны, но легко доступны. Длинные описания не ломают список.
- Действия доступны мышью и клавиатурой; важные действия не зависят только от наведения.
- При узком окне детали открываются отдельным представлением, а список остаётся читаемым.
- Короткие русские подписи: «Добавить задачу», «Выполнено», «Открыть сообщение».
- Действия, не меняющие текст описания задачи, находятся в верхней панели окна: срочность, источник, завершение, перенос и корзина. Над редактором остаётся только информационная строка метаданных без управляющих полей.
- Пустое состояние объясняет одно следующее действие. Ошибка сохраняет введённый текст и предлагает повторить попытку.

## Фирменный градиент

- Базовый мотив — компактный цветной squircle: коралловый, розовый и фиолетовый слои вокруг тёмного ядра, с ощущением глубины вместо плоской радуги.
- Использовать точечно: небольшой бренд-маркер, знак цитаты или состояние работы агента. Он не заменяет системные цвета срочности и состояния.
- Градиент живёт внутри отдельного небольшого объекта. Поверхность цитаты остаётся нейтральной; не растягивать цветную дымку на весь текстовый блок.
- Для приоритета использовать «градиентный сигнал»: короткий горизонтальный штрих вместо статусной точки или цветного бейджа. Важный — тёплый коралловый переход, срочный — контрастный красно-розовый.
- Текстовый статус в шапке может быть окрашен градиентом без фоновой плашки. Значение приоритета на подробных экранах всё равно дублируется текстом.
- Не использовать градиент как фон экрана, навигации, кнопки, строки задачи или большой декоративный блок.
- Одновременно использовать не более одного градиентного приёма в контенте; постоянный маленький бренд-маркер не считается отдельным приёмом. Белая и нейтрально-серая основа остаётся доминирующей.

## Границы

Не добавлять второй слой контейнеров поверх проектов, роли, спринты, конструкторы баз, сложные статусы, обязательные сроки или командную аналитику. Новые возможности вводить только по явному запросу пользователя.
