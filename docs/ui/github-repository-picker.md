# GitHub repository picker

[Индекс](README.md) · предлагаемый первый пилот · **контракт, не уже реализованная функция**.

## Решение и границы

Подключение repository к проекту открывает содержательный modal с поиском, фильтрами, выбором и явным commit. Это не обычный выпадающий список.

Причина не в количестве строк и не в моде на dialogs. Пользователь выбирает источник конкретного проекта, различает одинаковые имена в разных организациях, видит private/archived state и ограничения доступа. Ошибка выбора имеет последствия. Требуются устойчивое место для метаданных и отдельная точка подтверждения.

Простой dropdown слишком сжимает информацию; menu путает команды со значением; drawer без участия соседнего списка не даёт преимущества; отдельная страница разрывает короткий project-scoped сценарий. Combobox остаётся подходящим для простого значения, например сортировки или одного компактного поля. Search сам по себе не запрещает combobox.

**Разделить четыре операции:** авторизация аккаунта; предоставление GitHub App доступа; привязка источника к проекту Flood; разрешение агенту читать/изменять. Привязка не должна молча выдавать больше прав, клонировать repository или запускать синхронизацию, если это не отдельное заявленное действие.

## Точка входа

Project → Integrations → GitHub → «Подключить репозиторий». Заголовок/подзаголовок modal явно называют текущий проект. Если аккаунт не подключён, показать account connection state с явным действием; не изображать это пустым каталогом репозиториев.

```text
│ 24 результата · доступные этой установке источники          │
│                                                            │
│ ( ) owner/repository-a                   Приватный          │
│     Короткое описание                                      │
│ (●) team/repository-b                    Публичный          │
│     Короткое описание                                      │
│                                                            │
│ Не видите репозиторий? Управлять доступом в GitHub           │

│                                  Отмена   Подключить       │
└────────────────────────────────────────────────────────────┘
```

Controls нейтральные; logo обозначает provider, не окрашивает primary. Native select/компактный combobox допустим для фильтра организации **внутри** modal: сложность основного сценария не запрещает простые controls.

**Предлагаемая геометрия пилота:** max-width 720 px; внешние поля не меньше 16 px при достаточном viewport; max-height ограничена доступной высотой, ориентир 85dvh; внутренние padding 24 с переходом к 16 на узком окне; radius 16. Header/footer не прокручиваются вместе с каталогом, но не перекрывают focus. При очень узком окне почти полноэкранный layout, та же семантика и те же действия. Не задавать fixed height, которая обрежет длинный текст при zoom.

## Данные, поиск, фильтры

В проверенной версии `src/App.svelte` уже определены `GitHubRepositoryCatalog`, `GitHubInstallation` и `GitHubRepository`: доступны id, installation_id, full_name, description, private, archived, default_branch и owner_avatar_url. Это основание для рецепта, **не доказательство наличия server-side search/pagination**.

Начать с фильтрации действительно доступного каталога. Query сравнивает full_name и доступное description без учёта регистра. Owner/installation — отдельный фильтр; visibility — Все/Публичные/Приватные. Архивные по умолчанию скрыты, при включении явно обозначены. Не запрещать read-only источник только из-за archived; доступность конкретного действия определяется backend capability.

Полная identity — owner/repo. Avatar вспомогательный, отсутствие изображения не нарушает layout. Secondary metadata показывать только если она помогает выбрать; не превращать строку в таблицу из семи колонок. Уже связанный источник получает понятный state и не создаёт дубль.

Если каталог неполный, это видно: «Поиск среди загруженных»/«Загрузить ещё». Нельзя писать «Репозиторий не существует» по отсутствию в локальном списке. Управление доступом открывается явным действием во внешнем GitHub; после возврата есть Refresh, а не скрытая смена аккаунта.

## Selection и commit

Один radio selection в текущем сценарии. Не вводить multiple selection до подтверждения доменной поддержки. Клик выбирает draft, не подключает. Выбор хранится по устойчивому repository id вместе с installation context, не по индексу строки. При фильтрации сохраняется выбранный объект и его полная identity в footer; можно очистить выбор.

Footer показывает точный выбранный источник. «Подключить» недоступно до валидного выбора или при уже выполняющемся commit, причина понятна. Перед записью проверить актуальность project context/version и доступность источника через существующие APIs. Не расширять permissions из UI.

Во время записи не отправлять дубль. При success обновить project sources и подтвердить привязку. При ошибке сохранить query/filters/selection. Если запрос мог завершиться, сначала перечитать bindings; не обещать rollback и не повторять mutation вслепую. Если доступны idempotency/version checks, использовать существующий контракт; иначе явно выделить backend prerequisite.

## Keyboard contract

На открытии focus в search; dialog имеет связанный видимый title. Tab идёт по controls, выбранному/первому radio группы и footer; стандартные radio keyboard semantics сохраняются. Space выбирает radio; выбор не выполняет commit. Enter в search не подключает repository; явная кнопка подтверждения остаётся единственной точкой записи.

Не вкладывать внешнюю ссылку/другой button внутрь radio label как конфликтующий target. Сложные дополнительные действия вынести из selectable row. Escape сначала закрывает раскрытый фильтр, затем modal; focus возвращается к trigger. Фон недоступен. После обновления списка focus не прыгает сам.

## Обязательные состояния

| Состояние | Что видит человек / восстановление |
| --- | --- |
| Нет подключённого аккаунта | Подключить аккаунт; не пустая search выдача |
| First loading | Стабильная структура, спокойный loading |
| Refresh | Предыдущие результаты остаются, update indicator |
| Нет доступных repositories | Объяснение scope и управление доступом |
| Нет совпадений | Query сохранён, reset filters |
| Сессия истекла | Reconnect с сохранением локального выбора |
| Нет права на источник | Подтверждённая причина и управление доступом |
| Offline / rate limit | Достоверный статус, контролируемый retry |
| Уже подключён | Не предлагать повторную запись |
| Источник удалён/доступ отозван после выбора | Не выполнять commit, предложить обновить каталог |
| Project version conflict | Перечитать текущие bindings, не затереть чужие изменения |
| Неизвестен итог записи | Сверка состояния перед повтором |
| Успех | Источник виден в проекте; permission state указан отдельно |

## Приёмка пилота

Наборы: 0, 1, 50, 500 repositories; две организации с одинаковым repo name; private и archived; длинные имена/описания; нет avatar; уже linked; revoked permission; expired session; delayed и out-of-order ответы; double click commit; closed dialog during pending.

Пройти поиск → фильтр → выбор → изменение фильтра → commit/error/recovery целиком клавиатурой. Проверить light/dark, narrow, 200% zoom, focus return. Сверить identity выбранного и записанного источника. Любая неподдержанная capability отмечается как prerequisite, а не рисуется работающей.

Следующий шаг реализации: один feature component + typed catalog adapter + общий modal contract; не массовая переработка App.svelte. См. [миграцию](frontend-audit.md).
