## How to begin an implementation task

Read the operating contract, rule matrix, ownership/disclosure, foundations, selected direction and applicable skill. Then read only the relevant components and recipes. For the first project-overview slice use R03 with C01/C02/C03/C10/C20/C21 as applicable, then the verification and review workflow. Inspect existing code and unfinished changes before editing. Reuse the existing selected-direction study; new unresolved compound patterns use the research procedure.

Keep projects in the sidebar and tasks in one dominant workspace list. Task editor and project context are separate pages. One primary action, rare actions in overflow, normal urgency quiet in lists, important/urgent explicit. Ordinary controls stay monochrome; original blobs are sparse. Keep Tauri 2, Rust, Svelte 5, TypeScript, Vite, local Markdown truth, stable IDs, expected versions and shared UI/MCP mutation rules. No framework or architecture layer merely for restyling.

For a rules/skills request, finish documents and stop before implementation. For review, deliver findings; do not infer permission to change code. Follow the user's collaboration constraints. Do not silently lose drafts, overwrite external edits, send private context externally, or mark a task complete. The existing accept_agent_run operation is compound and must be labeled Принять и завершить.
