# Flood UI references

Начни с [реестра и метода](../../../docs/ui/references.md). Не собирай moodboard без сценария.

1. Назови нужную поверхность и Flood constraint: desktop density, task/context work, human decision или integration flow.
2. До отбора проверь реальный публичный launch и релевантное update по источникам самого продукта. Не путай founding, waitlist, launch и redesign.
3. Ищи в Mobbin один конкретный screen/flow. Проверь изображение и actual app identity, а не только metadata. Named query может вернуть другой продукт или сценарий.
4. Отдельно зафиксируй capture date. Если её нет, напиши unknown; дата в содержимом screenshot не является доказательством. Статус provisional не повышать молча.
5. Запиши переносимый принцип, отвергнутые детали и причину. Новизна не гарантирует пригодность; чужой стиль не заменяет Flood foundations.
6. Используй canonical mobbin_url для ссылки на каждый упомянутый экран. Для разрешённого сохранения изображения скачай оригинальный image_url; не используй low-res preview или expiring image link как постоянный источник.
7. Сохрани маленький реестр с launch/update/capture/checked dates, primary URLs, статусом и recheck trigger. Если свежих подходящих экранов нет, сообщи это и используй датированные primary материалы — не заполняй пробелы неподходящей выдачей.

Не копировать чужой component code/assets и не распространять screenshots без основания. OA Design — пример устройства документации, не стиль Flood. Этот skill не нужен для механического исправления уже определённого UI.
