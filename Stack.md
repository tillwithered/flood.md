# flood.md — утверждённый стек

Утверждено пользователем 9 сентября 2026 года. Цель — быстрое локальное десктоп-приложение с небольшим потреблением ресурсов. Первая целевая платформа — Windows.

| Часть | Технология |
| --- | --- |
| Десктопная оболочка | Tauri 2 |
| Ядро приложения, файлы и поиск | Rust |
| Интерфейс | Svelte 5 + TypeScript |
| Разработка и сборка интерфейса | Vite |
| Источник правды | Markdown с YAML front matter; одна задача — один файл |
| MCP | Официальный Rust SDK `rmcp`, транспорт stdio |

Точные совместимые версии зависимостей выбрать при реализации и зафиксировать lock-файлами. Требования к интерфейсу — в `Design.md`, правила работы агентов — в `AGENTS.md`.

## Архитектура

- Общее Rust-ядро отвечает за модель задач, проверку данных, чтение, поиск и запись файлов.
- Десктопный интерфейс вызывает ядро через команды Tauri. Svelte отвечает за отображение и взаимодействие; файловые операции выполняет Rust.
- Отдельный исполняемый MCP-сервер использует то же ядро и запускается MCP-клиентом по необходимости. Он должен работать при закрытом окне flood.md.
- Общая библиотека не защищает от одновременной записи разными процессами: предусмотреть межпроцессную координацию, проверку версии данных и атомарное сохранение.
- Vite нужен только при разработке и сборке. Выпущенное приложение загружает собранные локальные файлы интерфейса; постоянный Node.js-процесс или веб-сервер не нужен.
- Telegram добавляется отдельным модулем через TDLib. Проект в flood.md может хранить привязку к Telegram-чату; Telegram не меняет локальный источник правды. flood-buddy — последующий этап.

## Производительность

- Отслеживать изменения файлов событиями; не перечитывать всю папку по частому таймеру. Объединять серии событий и обновлять только затронутые задачи.
- Загружать подробный снимок сообщения при открытии задачи. Не блокировать интерфейс файловыми операциями и поиском.
- Не добавлять постоянные фоновые циклы, ненужные процессы, скрытые окна или непрерывные анимации.
- Локальная нейросеть не является частью стартового набора. Агент подключается через MCP.
- При необходимости разрешён восстанавливаемый индекс. Markdown остаётся единственным источником правды; отдельная БД пока не обязательна.
- Выбор Tauri не гарантирует конкретный расход RAM: WebView тоже использует ресурсы.

## Проверка перед готовностью

На release-сборке измерить время запуска, суммарную память процессов приложения и WebView, CPU в простое и отзывчивость списка на репрезентативном наборе задач. Указать оборудование и размер набора. Отдельно проверить MCP при закрытом окне и параллельное редактирование через интерфейс и MCP.

Численные бюджеты пока не установлены: не обещать мегабайты или время запуска без измерений.
