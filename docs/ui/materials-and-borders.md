# Материалы и границы

[Индекс](README.md) · контракт 0.2 · применяется при изменении chrome, borders, surfaces и depth. [Исполнимый образец](recipes/README.md).

## 1. Не обводить структуру DOM

Граница объясняет отношение, а не наличие контейнера в коде. Перед добавлением линии ответь: что без неё перестанет быть понятно? «Здесь div/card» — не ответ.

Порядок выбора: **выравнивание → пространство → разница поверхности → одна локальная линия → полный контур → elevation для реального наложения**. Это порядок рассмотрения, не обязанность использовать все ступени.

Если секция уже различима заголовком и отступом, рамка обычно не нужна. Если две панели разделены материалом, линия необязательна. Если строка принадлежит единому списку, не заключай каждую строку в отдельную card. Для ввода, состояния выбора и focus действуют более сильные требования ниже.

## 2. Пять разных ролей линии

| Роль | Где | Контракт |
| --- | --- | --- |
| None | Секции документа, обычные группы полей, метаданные | Не рисовать границу; использовать ось и расстояние |
| Divider | Реальная смена групп или регионов | 1 CSS px, локальная длина, низкий контраст; один владелец |
| Surface edge | Самостоятельная тихая панель или overlay | Слабый нейтральный контур; не делает панель кнопкой |
| Control boundary | Граница ввода/выбора, нужная для распознавания | Не наследует faint decorative token; достаточная различимость |
| Focus / state indicator | Keyboard target, selected, invalid | Отчётливый независимый индикатор, не исчезающий блик |

Нельзя использовать `--line` для всех пяти задач. Существующие `--line`/`--soft-line` не переопределять глобально ради одной новой поверхности: это затронет неизвестных потребителей. При пилоте добавлять/согласовывать именованные роли через один runtime token source.

## 3. Material presets вместо случайного набора эффектов

Выбирать **один базовый material**. Не складывать классы, каждый из которых добавляет собственные border, background и shadow.

| Material | Fill | Граница | Глубина | Пример |
| --- | --- | --- | --- | --- |
| Plain | Наследуемая | Нет | Нет | Секция контекста, текст документа |
| Quiet | Небольшая нейтральная смена тона | Обычно нет | Нет | Группа параметров, спокойная summary |
| Outlined | Background / surface | Один surface edge | Нет | Независимая область на близком фоне |
| Field | Field | Control boundary, когда нужна для распознавания | Обычно нет | Search/input/textarea |
| Floating | Непрозрачный elevated | Тихий edge | Contact + diffuse shadow | Menu, modal, transient inspector |
| Semantic | Warning/Danger/Success surface | Обычно без рамки | Нет | Сообщение о реальном состоянии |

Если форма говорит «выемка», не добавляй одновременно внешнюю тень, превращающую её в поднятую кнопку. Если панель находится в потоке страницы, не выдавай ей shadow модального окна. Z-index отражает фактическое наложение, не декоративный вес.

Compound appearance допустим: слабый край + контактная тень + рассеянная тень могут вместе описывать **один** floating material. Недопустимо складывать три независимо выразительных эффекта. Один главный сигнал глубины, остальные вспомогательные.

## 4. Прозрачность и реальная подложка

Низкий alpha — удобный способ подчинить декоративную линию окружению, а не магическое средство качества. Для непрозрачной однотонной поверхности equally valid заранее рассчитанный solid neutral. Выбираем по контексту, не по моде.

Стартовые значения образца, не accessibility thresholds:

| Роль | Light | Dark |
| --- | --- | --- |
| Divider | Ink около 7% alpha | Light ink около 8% |
| Surface edge | Ink около 10% | Light ink около 12% |
| Верхний декоративный свет | White около 72%, на белом почти исчезает | White около 14% |

Проверять итоговый пиксель на **фактической** поверхности. Alpha не равен контрасту; линия на canvas и та же линия на tinted status card выглядят по-разному. Для WCAG сначала вычислять композицию слоёв, затем luminance ratio. Декоративный фон поверх картинки не гарантирует стабильную читаемость; интерфейсные controls предпочитают непрозрачную поверхность.

Не уменьшать `opacity` всего контейнера для ослабления border: вместе с ним исчезнут текст, иконки и focus. Не ставить `opacity: .5` на error message. Не пользоваться `mix-blend-mode` как универсальным способом адаптации темы.

## 5. Мягкий верхний свет и неравномерный edge

Уместен на немногих действительно поднятых поверхностях: dialog, menu, иногда самостоятельный preview. В обычных rows, inputs и каждой секции света нет. Он не переносит стеклянную фактуру блобсов на весь продукт.

Простой `box-shadow: inset 0 1px 0 ...` даёт внутренний верхний акцент, но **не задаёт управляемое затухание вдоль горизонтали**. Для мягкого ухода к краям образец использует отдельный pseudo-element высотой 1 px: neutral/white `linear-gradient` от transparent через слабый свет обратно в transparent. Его концы отступают от углов; нет белой рамки по периметру. Реализация — `.material--top-light::before` в [materials.css](recipes/materials.css).

Это слой на внутренней верхней кромке: `pointer-events: none`, без изменения layout и hit area. Не применять overflow:hidden к целому интерактивному компоненту только ради блика. Focus остаётся снаружи и не обрезается. Декоративная графика не добавляется в accessibility tree.

Для закруглённого edge с различной интенсивностью по всему контуру возможен отдельный masked gradient rim. Он **не стандарт по умолчанию**: нужны доказанная необходимость, fallback, проверка mask/composite в целевых WebView и отсутствие clipping. Не вводить сложный CSS masking ради каждой маленькой кнопки.

Не анимировать положение блика вслед за мышью, не добавлять rainbow/glow и постоянный shimmer. На светлой поверхности едва заметный или невидимый блик нормален: не затемнять весь UI, чтобы продемонстрировать эффект.

## 6. Dividers и владение границей

Один стык — одна линия: sidebar рисует правую границу **или** content левую, не оба. Header bottom и следующий toolbar top не дублируются. Border на child и inset spread-shadow на parent не должны случайно давать 2 px.

Divider заканчивается на оси содержимого. В списке с leading avatar можно начинать линию после avatar, если она разделяет текстовые блоки; не менять inset случайно между соседями. Первая/последняя строка не получают лишних линий рядом с внешним контуром группы.

В dense collection допустим локальный divider, когда он реально помогает сканировать несколько колонок. Standalone action rows разделяются gap и имеют собственный hover area, но не обязаны иметь видимую рамку. В settings группы различаются spacing и headings; не оформлять каждую настройку одинаковым outlined box.

Scrollable body владеет scroll; header/footer могут отделяться линией, если к ним подходит прокрученный контент. Scroll shadow — сигнал скрытого содержимого, появляется только при соответствующем overflow. Не рисовать постоянный shadow там, где ничего не прокручивается.

## 7. Dark theme — не инверсия light

Использовать текущую нейтральную семью Flood. Не осветлять **все** edges до белого и не переносить чёрную тень light-темы без оценки её видимости. В dark роль разделения чаще несут небольшой сдвиг поверхности и слабый светлый край; shadow остаётся вспомогательным.

Не требовать, чтобы любой child был светлее parent: selected, field и overlay имеют разные роли. Контраст текста проверяется для каждой пары. Скриншот с большой чёрной областью не доказывает удобство полного рабочего дня.

## 8. Границы, которые нельзя сделать едва заметными

[WCAG non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) отличает обязательные cues от декоративного chrome. Required control/state information проверяется на 3:1 к соседним цветам; декоративный divider не обязан достигать того же значения. Hover wash может быть тонким, но не должен уничтожать исходную различимость.

Не объявлять border поля декоративным только потому, что у поля есть label. Пользователь должен найти область ввода. Outline нужен не каждой текстовой кнопке, но видимый focus нужен всем интерактивным целям. Selected не кодировать только почти незаметным серым фоном: добавить контрастную отметку/индикатор и правильное ARIA state.

Для Flood default focus — нейтральный 2 px outline с достаточным зазором от соседей; не fading gradient. 2 px — наш рабочий контракт, а не утверждение, что любой такой outline автоматически соответствует всем критериям. Проверить [Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html) отдельно; это критерий AAA.

`prefers-contrast: more`: убрать необязательные световые эффекты, усилить нужные края. `forced-colors`: сохранить реальные borders/outlines и system colors, не полагаться на shadow/gradient. [Поведение forced-colors](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/forced-colors). Системный Highlight может быть синим: доступность пользователя выше нашего нейтрального оформления.

## 9. Антипаттерны и исправление

| Антипаттерн | Исправление |
| --- | --- |
| Тёмная рамка у каждой секции | Убрать лишние контуры, оставить heading/space |
| Panel + card + outlined row вокруг одних данных | Один owner material, дочерние данные без нового chrome |
| Рамка ослаблена вместе со всем текстом | Alpha только у edge token |
| Selected виден только по почти белой заливке | Neutral mark + semantic state |
| Outer shadow + inset shadow + gradient rim на каждом control | Упростить material до одной понятной роли |
| Белая линия светится во всех dark cards | Уменьшить alpha/число линий, проверить surface separation |
| Цветной focus «чтобы было заметно» | Контрастный нейтральный outline |
| 1 px стал 2 px на hover | Border width зарезервирован; меняется цвет, не геометрия |

## 10. Приёмка материалов

Смотреть при 100%, а не только увеличенный фрагмент: в заполненном экране важнее общий шум. Проверить light/dark, DPR 1/2, масштаб ОС/окна, длинный текст и плотный список. Значимая линия не должна превращаться в волосок из-за transform/scale. У `.material--top-light` выключение эффекта не меняет понятность интерфейса.

У каждой видимой линии должна быть роль из таблицы. Отдельно измерить контраст required boundaries и focus; не повышать декоративные линии до 3:1 ради формальной галочки. Образец проверяет только перечисленные пары и геометрию; полная приёмка — [acceptance](acceptance.md).

Основания и даты: [исследование материалов](materials-research.md). Значения, recipe и правила применения разработаны для Flood, не скопированы из Linear или Geist.
