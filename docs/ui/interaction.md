# Поведение, доступность и interface copy

[Индекс](README.md). Эти требования не задают стиль Material/Fluent/Carbon; они определяют работоспособность выбранного Flood UI.

## State contract

Для каждой асинхронной области перечислить применимые состояния до реализации: idle/loaded, first loading, refreshing, empty, no results, recoverable error, unavailable, permission denied, conflict, submitting, success. Это состояния представления, не предложение добавить всё перечисленное в domain enum.

Loaded content не исчезает при refresh. Первую загрузку не показывать как empty. Ошибка одной интеграции не заменяет весь проект общей error page. Unknown, estimated и actual не смешиваются; процент без измеряемого знаменателя не рисуется.

Область сообщает: что происходит, к чему это относится, что можно сделать дальше. Persistent issue остаётся видимым, пока не устранён. Toast подходит для краткого подтверждения, не для единственной возможности принять решение.

## Forms и draft

Поле имеет видимый label и программную связь с ним; hint/error связан с полем. Обязательность понятна до отправки. Не использовать placeholder как единственное название. Не блокировать paste и обычное редактирование. Значения не сбрасываются при validation/network error.

Для формы Save показывает ошибки рядом и переводит focus к первой существенной. Не создавать недоступную кнопку без объяснения. Для selection workflow вроде repo picker commit до выбора недоступен обоснованно; рядом явно «Выберите репозиторий». Это не то же, что молча отключить отправку любой формы.

Autosave показывает saving/saved/error и учитывает версию объекта. После конфликта дать сравнить актуальное и draft, а не перезаписать автоматически. Ошибка сохранения не запрещает скопировать введённое. Переход с dirty state требует безопасного выхода.

## Search и длинные списки

Разделять query, filters, focused result и committed selection. Search сначала использует доступный scope; не обещает найти всё в аккаунте, если загружена только часть каталога. «Нет совпадений» включает reset filters. «Нет доступа» ведёт к управлению доступом, не к созданию нового объекта.

Локальный фильтр не требует сетевого debounce. Для remote search подобрать задержку по измерению, отменять/игнорировать устаревшие ответы, учитывать IME composition. Не переводить focus с поля на каждый ответ. Result count сообщать ненавязчиво, не читать заново все строки.

Длинный список сначала измерить на реалистичных данных. Pagination/virtualization выбирается по latency и DOM cost, не по модному имени библиотеки. При виртуализации проверить keyboard navigation, selection, accessible counts и сохранение видимости focused row. Не обещать мгновенный поиск без профиля.

## Асинхронная безопасность

В пределах одного commit не отправлять дубли. Доступный backend idempotency использовать, но не выдумывать поддержку параметра. При неизвестном результате сначала сверить состояние, затем предлагать повтор; retry не должен незаметно создавать второй объект.

При rate limit соблюдать доступный retry-after/состояние провайдера; не запускать бесконечный retry loop. UI не обещает точное время восстановления, если сервер его не сообщил. Offline не равен signed out. Reauthentication запускается явным действием и сохраняет локальную работу.

Cancel интерфейса, отмена запроса и откат завершённого действия — разные вещи. Закрытие modal не гарантирует rollback. Если операция продолжается, её итог доступен в исходной области; результат не теряется вместе с overlay.

## Клавиатура и focus

Использовать native button/input/label/table там, где они выражают сценарий. Не превращать все элементы в div с tabindex. Focus виден и не скрыт sticky header/footer. Порядок DOM следует reading order; не чинить его положительными tabindex.

Dialog ограничивает focus и делает фон неинтерактивным; немодальная detail pane этого не делает. После закрытия focus возвращается к trigger или логичному следующему объекту. Назначение initial focus зависит от действия: search у picker, заголовок у длинного содержательного dialog, безопасное действие у опасного подтверждения. [APG dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

Escape обслуживает верхний временный слой. Enter в textarea — новая строка; Enter в поиске не должен неожиданно подключать источник. Сочетания клавиш не отбирают стандартное редактирование, учитывают Cmd/Ctrl и раскладку. Drag-and-drop имеет кнопку/keyboard альтернативу. Focus не переносится из редактора на новый фоновой результат агента.

## Motion, scroll и zoom

Reduced motion сохраняет смысл без перемещения. Вкладки, overlay и inputs не ждут анимацию, чтобы стать интерактивными. Прокрутка одного container не должна случайно двигать скрытый фон. Автоскролл результата работает только пока пользователь у конца, иначе показать «Новые события».

Проверить 200% text zoom и длинные строки; размеры текстовых blocks адаптивны. Не отключать browser/webview zoom. Проверить system scrollbars и forced colors, не заставлять custom scrollbar скрывать доступный механизм.

## Copy как часть структуры

Использовать слова домена человека: задача, проект, источник, правило, навык, результат. Run ID и provider error code доступны в diagnostics, не заменяют объяснение.

| Не писать | Предпочесть |
| --- | --- |
| «Успешно!» | «Репозиторий подключён к проекту» |
| «Ошибка 403» | «Нет доступа к этому репозиторию» + действие восстановления |
| «Продолжить» в финале подключения | «Подключить репозиторий» |
| «Ничего нет» после поиска | «Нет совпадений» + «Сбросить фильтры» |
| «Агент закончил» при ready_for_review | «Результат готов к проверке» |

Это примеры структуры, не обещание, что любой 403 имеет одну причину. Показывать подтверждённую причину; неизвестную не додумывать. Не обвинять пользователя. Не писать, что изменение сохранено, до подтверждения записи.

Внутри контекста не повторять его название в каждом label. Helper объясняет последствия, а не пересказывает кнопку. RU и EN строки меняются вместе в существующей i18n системе; учитывать склонения/множественное число. Provider names, owner/repo, пути и код не переводить.

## Внешние guidelines

[Web Interface Guidelines Vercel](https://vercel.com/design/guidelines) полезны как инженерный checklist для focus, intrinsic layout и устойчивых inputs. Это не импорт целиком: Flood не наследует их Title Case, React assumptions, визуальные shadows или универсальные правила submit. При разногласии применимого стандарта и стилевой рекомендации выбирается доступность; например, zoom не отключается ради предотвращения mobile auto-zoom.
