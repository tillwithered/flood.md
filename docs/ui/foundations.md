# Foundations

[Индекс](README.md) · сохранённая база Flood + отмеченные ниже предложения для новых компонентов.

## 1. Характер и визуальный вес

Рабочая поверхность нейтральная и преимущественно плоская. Контент сильнее chrome; навигация слабее выбранного объекта; метаданные слабее названия. Прежде чем добавить рамку, попробуй выравнивание, интервал и типографику. Не ослабляй важный текст ради «воздушности».

Прямой AppShell сохраняется. Border отмечает реальную границу областей. Тень объясняет наложение, а не украшает каждый блок. Не соединять заметные shadow, border и tinted fill у обычной секции. Исключения требуют причины: например, край overlay должен читаться над неоднородным фоном.

## 2. Типографика

Golos Text, существующий локальный asset. Не добавлять новый шрифт ради отдельного экрана.

| Роль | Размер / line-height | Назначение |
| --- | --- | --- |
| Caption | 12 / 16 | Необязательная метаинформация |
| Compact | 13 / 18 | Короткие вторичные подписи и плотные controls |
| Body | 14 / 20 | Рабочий текст и стандартные actions |
| Lead | 16 / 24 | Вводный текст и крупный ввод |
| Section | 20 / 26 | Заголовок смысловой секции |
| Page | 24 / 32 | Заголовок рабочего экрана |
| Display | 32 / 40 | Редкий onboarding/brand момент, не заголовок каждого списка |

Основной текст и важные действия не уменьшать до caption. Ниже 12 px не опускаться. Семантический HTML heading не зависит от визуального размера. Рабочее предложение по весам: 400 body, 500 label, 600 heading; не запрещать существующие 650 до отдельного аудита. Сначала исправлять иерархию, потом вес.

Заголовки и кнопки — sentence case. Длинные названия в рабочей поверхности переносятся; в индексе допустим ellipsis с доступным полным названием. Не обрезать одновременно owner и repository: исчезнет различимость. Сравниваемые числа используют tabular numerals. Русские строки проверять настоящими словами, а не искусственным lorem.

## 3. Пространство и плотность

Базовая шкала: 4, 8, 12, 16, 24, 32; 48 и 64 для макрокомпозиции. Это не запрет border 1 px и не запрет измеренной оптической поправки.

| Отношение | Интервал | Пример |
| --- | --- | --- |
| Control | 4–8 | Иконка и label, label и helper |
| Construct | 12–16 | Поля одной формы, части row |
| Cluster | 24 | Группа связанных controls |
| Section | 32 | Разные смысловые секции |
| Region | 48 | Крупные области при достаточном пространстве |

Существующие tokens `--space-control`, `--space-construct`, `--space-cluster`, `--space-section`, `--space-region` уже задают 8/16/24/32/48. Использовать их прежде новых ролей. Не считать каждый вложенный `div` новым уровнем spacing. У одной пары соседей должен быть один владелец gap, не сумма margin обоих детей.

Для shell и широкого content использовать существующие `--page-gutter`, `--content-wide`; для чтения и настроек — `--content-reading` и `--content-settings`. Не растягивать строку документа до ширины монитора. Поля, заголовки и списки держат общую левую ось. Макроотступ на узком окне уменьшается раньше шрифта и hit area.

**Предложение для новых controls:** compact height 32, default 36, large 40 px. Это minimum, а не фиксированная высота многострочного текста. Icon target 32/36 при glyph 16/18/20. Существующие 34 px не менять массово без причины. Для coarse pointer целиться в 44 px. Минимум WCAG AA — 24×24 CSS px либо допустимые исключения по расстоянию; 44 — наш более удобный ориентир, не универсальное требование AA. [Источник](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

Два типа плотности: collection row экономит вертикальное место; standalone action получает больше воздуха. Не делать все строки высотой 64 и не пытаться исправить перегруженный экран шрифтом 11.

## 4. Форма

Сохранённая база: control radius 8–10, крупная внутренняя panel 14–18 px. **Предложенные именованные роли:** 8 compact, 10 standard, 16 panel/dialog. Pill только для компактного token/chip или действительно капсульного объекта; обычная кнопка не обязана быть pill. Внешний shell не скруглять дополнительно.

Для параллельных вложенных rounded-rect контуров: `inner = max(0, outer − inset)`. Считать расстояние между видимыми контурами с учётом border, а не механически вычитать padding. Пример: 16 − 6 = 10. Родитель и ребёнок используют связанную величину, не независимые magic numbers.

Это геометрия круглых углов, не универсальная формула для любой squircle или иллюстрации. Существующее `@supports (corner-shape: squircle)` — progressive enhancement; fallback с border-radius остаётся полноценным. Не добавлять clip-path, который срежет focus ring, текст или тень.

## 5. Цвет и материалы

Сохранять роли `--ink`, `--muted`, `--faint`, `--background`, `--canvas`, `--surface`, `--elevated`, `--field`, `--line`, `--soft-line`, `--hover`, `--selected`, `--on-ink`. Их текущие значения находятся в `src/styles.css`; не дублировать палитру в компоненте.

Primary: ink surface + on-ink label. Secondary: neutral surface/border. Hover и selected — нейтральные, focus — различимый нейтральный контур. Connector logo может оставаться узнаваемым, но не окрашивает кнопку «Подключить» в фирменный цвет сервиса.

Status использует отдельные semantic ink/surface и текст/иконку. Danger применяется в точке опасного действия; весь экран настроек не становится красным. Тонированная status surface — один материал, без чёрной вложенной карточки для count.

Проверять реальную пару foreground/background в обеих темах, включая hover и disabled explanations. Обычный текст ≥4.5:1, крупный ≥3:1. Важные для распознавания controls/состояний графические границы ≥3:1; декоративный divider не обязан превращаться в тяжёлую линию. [Текст](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [нетекстовый контраст](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). Не считать имя token доказательством доступности.

## 6. Блобсы, иконки, глубина

Предоставленные flood assets — полупрозрачные мягкие объёмы разных форм и цветов. Их назначение: brand, agent identity, редкий onboarding/empty-state акцент. Цвет формы не кодирует результат run. Рядом с агентом остаются имя и обозначение «Агент»; состояние показывается отдельно.

Не превращать рабочую область в wallpaper, controls в желе, а каждый loading в большой вращающийся blob. Не более одного крупного brand-момента на view; в заполненном task list обычно достаточно малого identity marker. Декоративные assets скрыты от assistive technology; смысловые имеют доступное название.

Использовать существующий Lucide и реальные provider logos. Одной операции соответствует одна иконка; не добавлять иконку к каждой строке только ради заполнения места. Вес и размер glyph согласовывать с соседним текстом. Не смешивать emoji и stroke icons в chrome.

## 7. Движение и ожидание

**Предлагаемый словарь для пилота:** feedback 120 ms, popover/tooltip 160 ms, dialog/drawer 200 ms. Один спокойный ease-out для появления, без bounce у форм и редакторов. Эти значения требуют проверки, не являются измерениями текущего приложения.

Движение поясняет появление, направление или связь; ввод и закрытие не ждут конца анимации. Не анимировать всё через `transition: all`. Предпочитать opacity/transform, не перезапускать motion при каждом обновлении данных. Reduced motion убирает перемещение/пружины, сохраняя понятное состояние. Не анимировать постоянный idle фон.

Загрузка не стирает уже полезные данные. Skeleton повторяет будущую геометрию, но не изображает несуществующий прогресс. Состояние операции доступно сразу; декоративный индикатор можно отложить, чтобы не мигал. Не задерживать готовые данные ради минимальной длительности красивой анимации.

## 8. Окно и платформенные ограничения

Проектировать от доступной ширины content, не от модели устройства. Минимальные content widths сначала измеряются на длинном RU тексте. Когда две панели не помещаются, detail заменяет list с явным Back; не сжимать три колонки до нечитаемых полос.

Проверять 200% text zoom, user text-spacing, forced colors, клавиатуру и всегда видимые scrollbars. Нейтральный scrollbar не должен делать прокрутку недоступной; в forced colors допустим системный вид. Не отключать zoom и не прятать обязательные actions при narrow layout.

В Tauri проверить window drag regions: интерактивные controls не должны перетаскивать окно вместо клика. Не утверждать поддержку CSS только по desktop Chrome preview.
