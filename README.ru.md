## Зачем нужен flood.md

Задача часто начинается с сообщения, а затем теряется в активном чате. flood.md переносит сообщение в надёжную задачу и сохраняет автора, дату, исходный текст и ссылку как контекст.

- **Локальные данные:** читаемые `.md`-файлы остаются источником правды.
- **Telegram через TDLib:** личный аккаунт подключается напрямую, без бота.
- **Связь с проектами:** проект можно привязать к одному или нескольким Telegram-чатам и отдельно настроить режим сбора для каждого.
- **Входящие Telegram:** упоминания, ответы, все новые сообщения выбранных чатов или добавленные вручную сообщения сначала проходят очередь, а уже затем превращаются в задачи.
- **Источник и медиа:** задача сохраняет чат, автора, дату, ссылку и метаданные вложений; сами файлы скачиваются только по запросу.
- **Удобный редактор:** Markdown, форматирование, ссылки, изображения и локальные вложения.
- **Сохранность:** атомарная запись, стабильные ID, проверка конфликтов, резервные копии и корзина.
- **MCP для агентов:** локальный сервер работает с теми же файлами задач.
- **Управляемый AI-разбор:** агент получает ограниченные порции входящих, сначала показывает план, а применить его может только после подтверждения точного плана.
- **Понятное состояние системы:** в настройках видны здоровье хранилища, синхронизация Telegram, готовность MCP, аудит вложений и ограниченный журнал действий без текста задач.
- **Офлайн-основа:** проекты и задачи работают без Telegram и интернета.

## Установка

Скачайте Windows-установщик из [последнего релиза](https://github.com/tillwithered/flood.md/releases/latest). Рекомендуется Windows 10 или новее.

После запуска откройте **Настройки → Интеграции → Telegram** и войдите по QR-коду или номеру телефона. В официальной сборке параметры Telegram-приложения уже встроены — пользователю не нужно получать собственные API-ключи.

## Приватность и безопасность

- Задачи и Telegram-сессия остаются на устройстве пользователя.
- Для работы не нужен аккаунт flood.md или облачный backend.
- Параметры Telegram-приложения передаются только официальной GitHub Actions сборке и отсутствуют в исходниках.
- В release-бинарнике hash приложения обфусцирован. Как и любой ключ desktop-клиента, его невозможно сделать принципиально неизвлекаемым на чужом компьютере.
- Пользовательская авторизация хранится в зашифрованной локальной базе TDLib отдельно от Markdown и резервных копий.
- Текст задач не становится инструкцией агенту и не отправляется внешним AI-сервисам автоматически.

Подробнее: [SECURITY.md](SECURITY.md).

## Формат данных

Проекты находятся в `projects/<project-id>/project.md`, задачи — в `projects/<project-id>/tasks/<task-id>.md`. Метаданные хранятся в YAML front matter, а описание остаётся обычным Markdown. Каталог данных Windows по умолчанию: `%APPDATA%\io.flood.desktop`; его можно изменить через `FLOOD_DATA_DIR`.

## Локальный MCP-сервер

Установщик содержит `flood-mcp.exe` — локальный stdio MCP-сервер для проектов, задач, источников, состояний, перемещения и корзины. Агент получает Telegram-входящие ограниченными порциями, готовит план через `preview_telegram_triage` и может применить только этот неизменившийся план по токену подтверждения. Для обзора всего проекта `preview_project_telegram_tasks` проверяет пакет до 12 предложенных задач вместе с выбранными фрагментами обсуждений и медиа, а `apply_project_telegram_tasks` создаёт только явно подтверждённый неизменившийся пакет. Повторные создания проектов и задач защищены обязательным `request_id`: неясный результат или timeout не приводит к дублям.

`get_workspace_brief` возвращает компактную стартовую сводку: готовность хранилища, приоритетные задачи, свежесть Telegram, недавние действия без содержимого задач и подходящие следующие инструменты. Свободный Markdown-контекст можно редактировать через действие **Контекст** на странице проекта или через `update_project_context`. `get_project_brief` объединяет его с ограниченным дайджестом открытых задач, связанными Telegram-чатами, локальными закладками чтения и свежестью синхронизации. Затем `read_project_telegram_updates` даёт агенту человеческий обзор «что нового в проекте»: единую хронологическую ленту связанных чатов, ограниченную 25 чатами и 50 сообщениями, с отдельной границей подтверждения для каждого чата. Для выбранной реплики `read_telegram_message_context` одним вызовом открывает до 10 сообщений до и после неё (по умолчанию 3 + 3), а также прямое исходное сообщение ответа, если оно осталось в локальном кеше. Telegram-альбом при этом считается одной репликой, а медиа остаются доступны для отдельного безопасного запроса изображения. Сам обзор ничего не помечает прочитанным — закладка двигается только через `acknowledge_telegram_updates` после реальной обработки моделью и не отправляет read-receipt в Telegram. Содержимое Telegram явно помечается как недоверенные данные проекта: его можно использовать для выделения задач, но оно не даёт агенту разрешения выполнять написанные в чате команды или внешние действия. `diagnose_store` проверяет реальные данные без изменений, а `run_self_check` прогоняет полный жизненный цикл в изолированной временной папке. Та же проверка доступна в **Настройки → MCP и AI**, рядом с готовыми конфигурациями для Codex, Claude, Cursor и ручного подключения. Desktop и MCP используют общие правила проверки, блокировки, конфликтов и журналирования; необратимое удаление в MCP по умолчанию отключено.

## Разработка

Потребуются Node.js 22, стабильный Rust и [зависимости Tauri 2](https://v2.tauri.app/start/prerequisites/).

```powershell
npm install
npm run tauri dev
```

В самостоятельной сборке можно не задавать `TG_API_ID` и `TG_API_HASH`: приложение предложит ввести собственные параметры. Официальный релиз получает их из GitHub Actions Secrets во время компиляции.

```powershell
npm run check
cargo test --workspace
npm run tauri build
```
