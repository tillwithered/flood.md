Показываем состояние, не устраиваем представление.

Первый load, refresh, измеримый прогресс и результат операции — разные вещи. Цвет появляется только у реального semantic state.

Первый load и refresh не выглядят одинаково

Skeleton резервирует будущую геометрию. Refresh оставляет полезные данные на месте и показывает локальную активность.

Toast — краткий итог, не центр управления

Не крадёт focus, не хранит критическую ошибку и не дублирует одно событие banner+toast+badge одновременно.

Toast stack закреплён внутри этой демонстрационной области. В продукте — локальный floating layer. Максимум три видимых сообщения.

Timing candidate: passive success/info — 5 c; Undo — 8 c. Hover или keyboard focus приостанавливают таймер. Ошибка, требующая решения, не auto-dismiss toast — это inline/banner.
