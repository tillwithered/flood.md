## T-01. Сначала текст, затем контейнер

Внутри содержательного артефакта приняты четыре уровня: контекст 13/18, заголовок 20/26 weight 600, рабочий текст 14/20 weight 400, метаданные 13/18 weight 400. Для строки коллекции заголовок остаётся 14/20 weight 500: не переносить крупный title на каждую задачу. Это композиции существующей шкалы, не новая шкала шрифтов.

Расстояние между крупными текстовыми блоками — 16; внутри единой группы metadata — 6 в этом образце, как оптическое уточнение, а не новый обязательный глобальный space token. Изменение принятого spacing требует отдельного утверждения; автоматически добавлять token на каждое число не нужно. Важные permissions и ошибки не понижаются до нечитабельной подписи.

A/B имеет одинаковые строки, порядок, фон и ширину. Меняются только роли текста и интервалы. Удаление длинной строки, источника или неудобного состояния не является улучшением типографики. Метаданные не нужны внутри отдельных pills, если они не фильтры и не самостоятельные категории.

Длинное название переносится целиком. Нижняя граница размера текста 12 сохраняется. Вес не меняется на hover. Не добавлять новый шрифт, letter-spacing ко всему интерфейсу или uppercase всех подписей. Выбранные веса требуется проверить с настоящим Golos Text в Tauri; системный fallback не является доказательством font metrics.

## L-01. Плотность без потери содержимого

Одна коллекция, а не card на каждую строку. Анатомия demo-row: checkbox для группового выбора → название и источник → состояние → время. Название получает остаток ширины; время выровнено, tabular numbers. Статус окрашен только при реальном Warning/Danger/Success и продублирован текстом.

Обычная и плотная версии используют один массив из 18 задач и один шрифт. Меняются вертикальные отступы: 14 против 6, минимальная высота 70 против 54; многострочный текст увеличивает строку. Приняты два допустимых варианта для разных сценариев, **не автоматически новая настройка продукта или единый default для всех экранов**. Размер и состав метаданных не меняются. На narrow вторичные значения переносятся под название, а не скрываются.

Тумблер шума добавляет к тем же данным лишние рамки и pills для сравнения. Это антипаттерн, не утверждённый альтернативный стиль. Он не делает содержимое короче в чистой версии. Групповой checkbox не завершает задачу. В реальном продукте открытие задачи и bulk-selection должны иметь разные элементы управления; не вкладывать button в button/label.

Selection хранится по stable ID, не по индексу отфильтрованного массива. Поиск и фильтр сохраняют скрытое выбранное, а summary сообщает его количество. Clear filter не значит clear selection. Не применять bulk action ко всем невидимым результатам без явного scope. В демо нет write-операций.

## C-01. Один ряд — одна базовая геометрия

Для сравниваемого ряда приняты 36 px minimum height, radius 10, horizontal inset 12, glyph slot 16, gap glyph-label 8. Содержание может расширить control; minimum не становится фиксированным потолком. Coarse pointer повышает target до 44. Существующие 34 px в приложении не меняются массово одним селектором.

Поле, фильтр и primary имеют одинаковую ось, но разные роли: поле получает необходимую границу, secondary — спокойную заливку, primary — ink/on-ink. Не обводить каждый элемент столь же контрастно, как input. Граница поля не обязана быть такой же слабой, как декоративный край панели.

Иконки показываются в одинаковом slot, по одному stroke-языку. В specimen четыре простых собственных SVG; в production использовать существующий Lucide и реальные logos, не вводить параллельную библиотеку. Направляющие и slot outline — режим проверки, не дизайн продукта.

Ожидание сохраняет label и зарезервированное место индикатора. Повторный submit блокируется до конца локальной симуляции. В реальной операции сохранять actual state и не вводить искусственную минимальную задержку. Disabled объясняется рядом; tooltip и пунктир не обязательны. Validation удерживает draft и переводит focus на ошибочное поле.

Поисковый ряд здесь — обычная группа controls, не role=toolbar. Если понадобится ARIA toolbar, реализовать соответствующее управление фокусом, а не добавить роль ради названия CSS-класса. [WAI-ARIA toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/).

## S-01. Один сигнал — одно значение

- Hover: временная нейтральная обратная связь, не выбранное значение.
- Selected: устойчивое значение + подходящая метка (native radio/checkbox или check), спокойная поверхность.
- Focus: отдельный контрастный контур позиции клавиатуры; существует одновременно с selected/invalid.
- Current navigation: отдельная семантика текущей страницы/вкладки, не checkbox выполнения.
- Disabled: невозможность действия сейчас с доступной причиной.

Не складывать автоматически жирный title, чёрную боковую полосу, галочку и дополнительную рамку. Для radio/checkbox выбранная поверхность и сам indicator уже сообщают выбор; боковая полоса не нужна по умолчанию. Для навигации может быть оправдан другой contract. У tab сохраняется нейтральный индикатор текущего представления, но нет внешней капсулы вокруг всей полосы.

Форма/hit area не меняются между states. Статичная матрица из шести примеров не имитирует реальный focus для assistive technology; настоящая radio group ниже работает отдельно. Цвет метки и границы проверяется на соседней фактической подложке, не по имени token. [W3C non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

## Визуальное утверждение

T-01, L-01, C-01 и S-01 утверждены явным сообщением владельца после просмотра превью: «нравится, закидывай в мейн.» Дата и границы записаны в decisions.md. Чистые варианты приняты; намеренно шумные и несогласованные варианты остаются сравнительными антипаттернами.

Каждая вкладка сохранённого образца имеет свои Оставить / Доработать / Пока не решил и комментарий. Эта форма пригодна для последующих отзывов, а исходные подписи предложений — часть показанной лаборатории, не актуальный статус правил. Пока новый отзыв не передан обратно, это только локальные данные страницы; GitHub не меняется. Экспорт JSON не является командой автоматического merge.

При следующем изменении решения обновить соответствующий ID в decisions.md, указать принятую версию/ограничения и только затем переносить контракт в рабочий компонент. Отвергнутый пример сохраняется явно как rejected/baseline, а не остаётся активным правилом в соседнем документе. Не перегружать agent context: читать один затронутый раздел, не весь handbook.
