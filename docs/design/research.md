## Project-owned Mobbin procedure

Mobbin is already callable in this session. No global skill/plugin/config installation was performed. Its official skill can be used as research guidance; the project contract retains authority over product decisions. The current tool schema is authoritative when upstream skill text differs about tool names, image URL lifetime or export behavior.

1. Name the unresolved design question, current Flood surface and constraint. Skip fresh research for routine implementation of an established contract. New compound patterns or changed anchor compositions use a 3–5-product reference pass. The recorded Quiet Workbench study already supports the selected composition; implementing that recipe does not require repeating its research.
2. Use `platform: "web"` for comparable desktop information architecture; Mobbin has no desktop platform option. Do not imply that web references validate Windows window behavior.
3. Use one screen intent per `search_screens` call or one journey per `search_flows` call. Start with a small set, inspect relevance, then narrow. `search_sections` is for website sections and is usually irrelevant to the desktop product.
4. Provide a generic English `task_intent` consistently across one research task. Never send private tasks, project documents, chat contents, credentials or screenshots of the user's workspace as query context without explicit authorization.
5. Read the returned images. Record actual app identity, canonical `mobbin_url`, capture date or unknown, observed elements, transferable reasoning, rejected details and affected rule/component. For production reference adoption, verify a dated official product release/article independently; image metadata alone is insufficient.
6. If a result is irrelevant, reject it explicitly; popularity is not evidence that it suits Flood. Derive a Flood-specific behavior and test it against local data, Russian text, keyboard and minimum window size.
7. If exporting an image is requested, follow the current connector instruction for the high-resolution `image_url`, license/access terms and local artifact handling. Inline preview images and expiring image URLs are not permanent documentation assets. This package stores canonical links and observations only.
8. If Mobbin is unavailable, report that fact and use already verified project evidence or official documentation for a bounded specification. Do not invent observations or bypass access. A production change still respects any active live research gate; propose its amendment separately if it blocks work unnecessarily.

Optional installation of the official skill later should pin/review the upstream version and make it available as research support, without replacing project-owned rules or copying its “trigger aggressively” language into always-on project guidance. No network research is a prerequisite for a user to operate flood.md offline.
