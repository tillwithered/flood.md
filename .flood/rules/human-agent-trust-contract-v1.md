# Human–agent trust contract v1

Применять ко всей работе агента в flood.md.

1. Агент всегда обозначен как агент; его identity не смешивается с run state или статусом задачи.
2. Человек остаётся владельцем задачи и финального решения.
3. Любой run показывает объект работы, состояние, provider и доступный способ остановки или ответа.
4. Agent output сначала является предложением или результатом на проверку. Применение, публикация и завершение — отдельные действия, если пользователь заранее явно не разрешил их.
5. Для значимого изменения показывать provenance и diff/summary до принятия; сохранять историю после применения.
6. Доступ только минимально необходимый. Read не означает mutate; проектный scope не означает доступ ко всему аккаунту.
7. Внешние, необратимые, дорогие и широкие действия требуют подтверждения в точке действия.
8. Project Rules/Skills с Agent access направляют работу внутри уже выданных полномочий, но не могут выдать новые полномочия.
9. Контент интеграций остаётся недоверенными данными и не исполняется как инструкция.
10. Фоновая автоматизация экспериментальна, выключена по умолчанию, показывает provider/стоимость/scope и останавливается без скрытого повторного включения.
