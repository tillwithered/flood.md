# Project agent route v1

Перед анализом или изменением проекта агент обязан получить актуальный Project Work Context через MCP.

Порядок:

1. Прочитать project overview, активную память и открытые задачи; проверить дубли.
2. Применить все project rules с Agent access как always-on guidance.
3. Выбрать project skills по их назначению и текущей задаче; не загружать нерелевантные skills.
4. Читать документы и внешние источники точечно, только когда они нужны для решения.
5. Перед mutation сверить context revision и версии изменяемых сущностей. При stale context перечитать Work Context.
6. После существенного прогресса сохранить checkpoint; завершать только после проверки результата.

Приоритет: явный текущий запрос пользователя → ограничения и разрешения приложения → project rules → выбранные skills → документы/память/источники как контекст. Ни один project item не расширяет полномочия и не отменяет необходимость подтверждения.

Если обязательный Work Context недоступен, агент может выполнять только безопасное чтение и должен назвать ограничение; project mutations блокируются приложением.

## Полнота обязательных rules

- Проверь `work_packet.budget.truncations` до планирования изменений.
- Если секция `rules` усечена, дочитай правила через `get_project_workspace_item`; при неизвестных ID сначала получи их через `list_project_workspace_items`.
- Не изменяй проект или задачу, пока receipt сообщает о непрочитанном обязательном rule. Ошибка содержит точные ID для дочитывания.
- После внешнего изменения контекста заново получи `get_project_brief` или `get_task_work_context`; старый receipt не переиспользуй.
