# Visual foundations v1

Применять ко всем новым и изменяемым UI-поверхностям flood.md.

1. Перед проектированием прочитать документ «Визуальные foundations flood.md» и выбрать семантические роли, а не локальные размеры и цвета.
2. Использовать Golos Text. Типографика: caption 12/16, compact 13/18, body 14/20, lead 16/24, section 20/26, page 24/32, display 32/40. Случайные промежуточные размеры запрещены без изменения foundations.
3. Видимый текст не меньше 12 px; основные действия и обязательная информация не могут существовать только как caption или faint.
4. Контраст: обычный текст ≥ 4.5:1, крупный текст ≥ 3:1, значимые boundaries/focus/graphics ≥ 3:1. Цвет не является единственным носителем состояния.
5. Отступы используют шкалу 4/8/12/16/24/32; 48/64 только для макро-композиции. Layout управляет межкомпонентным gap. Локальные произвольные margin запрещены.
6. Цвета задаются семантическими tokens. Literal hex в компоненте допустим только для уникального иллюстративного asset, не UI-роли.
7. Нейтральная основа остаётся графитово-чёрно-белой. Brand-material коралл → розовый → фиолетовый не заменяет danger/success/attention.
8. Блобсы — смысловые акценты: максимум один крупный master на view; glyphs используются по установленной семантике. Не делать из блобсов wallpaper или универсальную заливку controls.
9. UI обязан выдерживать светлую/тёмную тему, узкое окно, 200% text zoom, длинный русский текст и reduced motion.
10. Сначала foundations, затем измеряемый аудит, contracts и anchor surfaces. Не начинать массовый screen-by-screen restyle до проверки системы на обзоре проекта, редакторе задачи и контексте проекта.

11. Все controls монохромны: цвет не используется для selected, hover, focus, primary или connector action. Исключения — семантические status/urgency, destructive confirmation, flood identity и живой progress. Заметные scrollbars кастомные, нейтральные, без системных стрелок и со stable gutter.

12. Status-card может иметь мягкий семантический tone, но обязана оставаться одним материалом: без контрастной вложенной card, чёрного count или отдельной тёмной строки. Внутренние элементы наследуют поверхность и разделяются divider/transparent tone shift; обычные controls остаются монохромными.

13. Крупная кликабельная row всегда оформляется как rounded-control с radius 8–10 px, neutral surface и gap 8–12 px до соседних controls. Не использовать квадратный hover, склеенные строки или постоянные dividers между самостоятельными actions.

14. Spacing семантичен: control 4–8, construct 12–16, cluster 24, section 32, region 48 px. Во вложенном compound construct внутренний gap меньше внешнего; parent владеет расстоянием между peers.
15. Канонический horizontal tab bar повторяет Settings: один нижний разделитель на полосе, без внешней capsule/shadow; верхняя линия не дублирует границу шапки, rounded neutral surface только у active tab, скрытый scrollbar на узком окне.

## Вложенные радиусы A − B = C

- Для параллельных вложенных контуров вычисляй внутренний радиус по формуле `C = max(0, A − B)`, где `A` — внешний radius, а `B` — фактический inset между видимыми контурами.
- Внешний и внутренний radius должны происходить из связанных tokens или CSS `calc()`, а не задаваться независимо.
- Пример: panel 16 px + inset 6 px → inner control 10 px. Это обязательно для inset panels, card-inside-control, grouped actions и карточек задач внутри округлённых секций — например task cards внутри «Моего фокуса».
- Pills, круги, непараллельные и намеренно асимметричные формы используют собственный shape contract и не подгоняются под формулу.
