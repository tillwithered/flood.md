## Зачем нужен flood.md

Задача часто начинается с сообщения, а затем теряется в активном чате. flood.md переносит сообщение в надёжную задачу и сохраняет автора, дату, исходный текст и ссылку как контекст.

- **Локальные данные:** читаемые `.md`-файлы остаются источником правды.
- **Telegram через TDLib:** личный аккаунт подключается напрямую, без бота.
- **Коннектор GitHub App:** вход через GitHub, выбор репозиториев и связь с проектами без персональных токенов и прав на запись.
- **Связь с проектами:** проект можно привязать к одному или нескольким Telegram-чатам и отдельно настроить режим сбора для каждого.
- **Входящие Telegram:** упоминания, ответы, все новые сообщения выбранных чатов или добавленные вручную сообщения сначала проходят очередь, а уже затем превращаются в задачи.
- **Источник и медиа:** задача сохраняет чат, автора, дату, ссылку и метаданные вложений; сами файлы скачиваются только по запросу.
- **Удобный редактор:** Markdown, форматирование, ссылки, изображения и локальные вложения.
- **Сохранность:** атомарная запись, стабильные ID, проверка конфликтов, резервные копии и корзина.
- **MCP для агентов:** локальный сервер работает с теми же файлами задач.
- **Управляемый AI-разбор:** агент получает ограниченные порции входящих, сначала показывает план, а применить его может только после подтверждения точного плана.
- **Понятное состояние системы:** в настройках видны здоровье хранилища, синхронизация Telegram, готовность MCP, аудит вложений и ограниченный журнал действий без текста задач.
- **Офлайн-основа:** проекты и задачи работают без Telegram и интернета.

## Установка

Скачайте Windows-установщик из [последнего релиза](https://github.com/tillwithered/flood.md/releases/latest). Рекомендуется Windows 10 или новее.

После запуска откройте **Настройки → Интеграции**. В Telegram можно войти по QR-коду или номеру телефона. GitHub подключается через официальный GitHub App: после входа выберите доступные репозитории и свяжите их с проектами flood.md.

## Приватность и безопасность

- Задачи и Telegram-сессия остаются на устройстве пользователя.
- Для работы не нужен аккаунт flood.md или облачный backend.
- Параметры Telegram-приложения передаются только официальной GitHub Actions сборке и отсутствуют в исходниках.
- В release-бинарнике hash приложения обфусцирован. Как и любой ключ desktop-клиента, его невозможно сделать принципиально неизвлекаемым на чужом компьютере.
- Пользовательская авторизация хранится в зашифрованной локальной базе TDLib отдельно от Markdown и резервных копий.
- Access и refresh token GitHub хранятся в системном хранилище учётных данных. В Markdown и резервную копию попадают только выбранные URL репозиториев и публичные метаданные.
- Доступ GitHub остаётся read-only и одновременно ограничивается установкой GitHub App и явной привязкой репозитория к проекту flood.md.
- Текст задач не становится инструкцией агенту и не отправляется внешним AI-сервисам автоматически.

## Формат данных

Проекты находятся в `projects/<project-id>/project.md`, задачи — в `projects/<project-id>/tasks/<task-id>.md`. Метаданные хранятся в YAML front matter, а описание остаётся обычным Markdown. Там же проект может содержать до 20 структурированных источников контекста: репозиторий, локальную папку, Figma, документацию, сайт или другой адрес. Хранятся только понятные ссылки и пути — не токены и не пароли. Доступ агента включается пользователем отдельно для каждого источника; новый или изменивший адрес источник всегда закрыт. Каталог данных Windows по умолчанию: `%APPDATA%\io.flood.desktop`; его можно изменить через `FLOOD_DATA_DIR`.

## Локальный MCP-сервер

Установщик содержит `flood-mcp.exe` — локальный stdio MCP-сервер для проектов, задач, источников, состояний, перемещения и корзины. Агент получает Telegram-входящие ограниченными порциями, готовит план через `preview_telegram_triage` и может применить только этот неизменившийся план по токену подтверждения. Явная команда в текущем запросе — например, «найди поручения и добавь их в проект» — уже разрешает применить проверенный план в том же ходе; для запроса «покажи, что нашёл» агент останавливается на preview. Для обзора всего проекта `preview_project_telegram_tasks` проверяет пакет до 12 предложенных задач вместе с выбранными фрагментами обсуждений и медиа. Повторные создания проектов и задач защищены обязательным `request_id`: неясный результат или timeout не приводит к дублям.

Готовый сценарий: «В проекте “zakup.io” проверь свежесть Telegram, найди явные поручения от Димы, при необходимости открой соседние сообщения, скриншоты и разрешённые GitHub-репозитории, затем создай задачи и расставь срочность». После создания агент открывает любую задачу через `get_task_work_context` и получает её описание, сохранённое обсуждение, медиа и разрешённые источники проекта для выполнения.

`get_workspace_brief` возвращает компактную стартовую сводку: готовность хранилища, приоритетные задачи, свежесть Telegram, недавние действия без содержимого задач и подходящие следующие инструменты. Действие **Контекст** на странице проекта редактирует свободный Markdown и структурированные ссылки на рабочие материалы в одном окне, задаёт разрешение агента для каждого источника и сохраняет всё атомарно; MCP использует `update_project_context` и `set_project_resources`, но не может включить доступ самостоятельно. `get_project_brief` объединяет Markdown, источники, состояние разрешения и подсказку подходящего способа доступа с задачами и Telegram. Для явно разрешённого локального репозитория или папки `list_project_resource_files` возвращает ограниченное дерево, а `read_project_resource_file` читает один выбранный UTF-8 файл. Оба инструмента остаются внутри заданного корня, пропускают генерируемые папки и похожие на секреты файлы и помечают содержимое как недоверенные данные проекта. Figma и веб пока остаются ссылками для внешнего коннектора. Затем `read_project_telegram_updates` даёт агенту человеческий обзор «что нового в проекте»: единую хронологическую ленту связанных чатов, ограниченную 25 чатами и 50 сообщениями, с отдельной границей подтверждения для каждого чата. Для выбранной реплики `read_telegram_message_context` одним вызовом открывает до 10 сообщений до и после неё (по умолчанию 3 + 3), а также прямое исходное сообщение ответа, если оно осталось в локальном кеше. Telegram-альбом при этом считается одной репликой, а медиа остаются доступны для отдельного безопасного запроса изображения. Сам обзор ничего не помечает прочитанным — закладка двигается только через `acknowledge_telegram_updates` после реальной обработки моделью и не отправляет read-receipt в Telegram. Содержимое Telegram явно помечается как недоверенные данные проекта: его можно использовать для выделения задач, но оно не даёт агенту разрешения выполнять написанные в чате команды или внешние действия. `diagnose_store` проверяет реальные данные без изменений, а `run_self_check` прогоняет полный жизненный цикл в изолированной временной папке. Та же проверка доступна в **Настройки → MCP и AI**, рядом с готовыми конфигурациями для Codex, Claude, Cursor и ручного подключения. Desktop и MCP используют общие правила проверки, блокировки, конфликтов и журналирования; необратимое удаление в MCP по умолчанию отключено.

`search_project_resource` дополняет локальный коннектор ограниченным поиском строк без учёта регистра: агент сначала находит релевантный код, а затем читает конкретный файл вместо загрузки всего репозитория. Для связанного GitHub-источника `get_github_repository_context` возвращает ограниченные метаданные, README, открытые issues и pull requests, а `list_github_repository_files`, `search_github_repository` и `read_github_repository_file` дают явный read-only доступ без клонирования и раскрытия токенов.

Для разбора входящих `get_project_triage_context` объединяет ограниченный бриф проекта, уже открытые задачи и хронологическую ленту нового из Telegram, не двигая закладки чтения. Агент может открыть выбранную реплику или скриншот, поискать в разрешённом репозитории и передать точный пакет в `preview_project_telegram_tasks`; дополнительный вопрос не нужен, если текущий запрос уже явно разрешает создание.

Для существующей задачи предпочтительной точкой входа стал `get_task_work_context`. Он возвращает Markdown-задачу, ограниченный контекст проекта, разрешения источников и центрированное Telegram-обсуждение из актуального локального кеша. Если сообщение уже вышло из скользящего кеша, используется снимок, сохранённый вместе с задачей. Медиа по-прежнему запрашиваются отдельно и только по необходимости.

Локальный stdio-сервер напрямую работает в desktop MCP-клиентах, которые умеют запускать локальную команду: например, Codex, Claude Desktop и Cursor. Обычный облачный чат ChatGPT локальный `.exe` запустить не может: по официальному MCP-интерфейсу OpenAI ему нужен доступный по HTTPS remote MCP-сервер. Такой сетевой мост намеренно не входит в локальную версию flood.md, чтобы не передавать Telegram и задачи в облачный backend.

## Разработка

Потребуются Node.js 22, стабильный Rust и [зависимости Tauri 2](https://v2.tauri.app/start/prerequisites/).

```powershell
npm install
npm run tauri dev
```

В самостоятельной сборке можно не задавать `TG_API_ID` и `TG_API_HASH`: приложение предложит ввести собственные параметры. Для встроенного GitHub App задайте `FLOOD_GITHUB_CLIENT_ID` и `FLOOD_GITHUB_APP_SLUG`; без них локальная сборка покажет поля для собственного GitHub App. Включите Device Flow и оставьте только read-права Metadata, Contents, Issues и Pull requests. Официальный релиз получает параметры Telegram из GitHub Actions Secrets, а публичные значения GitHub App — из Actions Variables.

```powershell
npm run check
cargo test --workspace
npm run tauri build
```
