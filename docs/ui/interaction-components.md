## M-01. Команда — menu

Контекстное меню содержит глаголы одного объекта: посмотреть, закрепить, удалить. Не превращать его в форму, редактор или каталог источников. Показывать имя текущего объекта рядом с trigger; размещать menu от его фактической геометрии, с отступом 6 px, защитой 12 px от края viewport и раскрытием вверх при нехватке места. При прокрутке якорь и popup остаются связанными; вне viewport popup закрывается, не перетягивая фокус.

Пилот: width 260, radius 14, inset 6, item minimum 36, radius 7. Это согласованный вложенный контур (1 px edge + 6 px inset), не новый универсальный размер. Одна локальная floating-тень, один тихий край. Не затемнять всю страницу для трёх команд. Группы разделены только при смене намерения. Иконка не обязательна у каждой команды.

Enter/Space открывают, ↑/↓ перемещают, Home/End ведут к краям, ввод буквы ищет команду. Escape закрывает меню и возвращает focus в trigger. Tab закрывает и продолжает обычный порядок. `aria-haspopup=menu`, `aria-expanded`, menu/menuitem описывают настоящее поведение, не только форму. [WAI menu button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/) и [menu keyboard](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/).

Команда удаления в меню нейтральна и ведёт в короткое подтверждение со scope. В подтверждении — розово-красное действие; начальный focus на Cancel. В лаборатории удаляется только демо-задача с восстановлением. Это не контракт реального удаления данных Flood.

## V-01. Значение — select или combobox

Короткие взаимоисключающие значения используют select. Native popup оставляем системным там, где WebView не поддерживает корректную кастомизацию; не обещать pixel-identical OS menu. Монохромен собственный control; forced-colors пользователя важнее авторской палитры.

Если одно значение нужно искать, используем editable combobox с listbox. Это не menu и не dialog. Query, active option и committed value — разные состояния. DOM focus остаётся в input, active option связана через `aria-activedescendant`. ↑/↓ двигают active, Enter выбирает только active; Escape отменяет незавершённый ввод и восстанавливает сохранённое значение. Tab закрывает popup без произвольного выбора первой строки. [WAI combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).

Пустая выдача сообщает о запросе, не об отсутствии проекта вообще. Внутри option нет отдельных links/buttons. Popup соответствует ширине поля с ограничением viewport; длинное имя переносится. Сплошной search-list не состоит из вложенных cards. Выбранный объект отмечен check, активный с клавиатуры — отдельной neutral surface/границей. Mouse hover не переписывает committed value.

Образец выбирает проект только в памяти. Полноценный асинхронный combobox требует отмены/игнорирования устаревших ответов, пагинации и отдельного тестирования; локальный список этого не доказывает.

## D-01. Завершённый сценарий — dialog

См. существующий [полный контракт GitHub picker](github-repository-picker.md). Здесь первая интерактивная демонстрация, не готовая integration implementation.

Три уровня: identity проекта/аккаунта → поиск и фильтры → результаты. Footer содержит полный owner/repository и отдельное подтверждение. Нет badge на каждом значении; приватность и архив — читаемые метаданные. Архивность не запрещает чтение автоматически. Авторизация, GitHub App scope, привязка источника и права агента — отдельные операции.

Уточнение 0.5.1: privacy/linked/archive/access — независимые краткие признаки справа в блоке названия; при переносе остаются до описания. Лёгкие нейтральные метки не являются кнопками. «Подключён» не скрывает «Приватный/Публичный». Полный [контракт метаданных](repository-metadata.md) применяется и на узком окне.

Каталог в образце содержит 10 синтетических объектов, два одинаковых repo name у разных владельцев, длинное имя и архивы. Selection хранится по installation+repository ID, переживает query/filter и явно показана, даже когда строка скрыта. Enter в search не подключает источник. Список не создаёт второй keyboard menu: native radio с обычной семантикой single selection.

Native `dialog.showModal()` делает фон inert. Видимый заголовок связан через `aria-labelledby`, начальный focus — search. Tab остаётся внутри, Escape закрывает текущий диалог, focus возвращается в trigger. Клик по backdrop не теряет выбор; закрытие без записи сохраняет локальный draft в пределах страницы. Выбор репозитория не является несохранённым документом: отдельное предупреждение об утрате текста здесь не требуется. [WAI modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

Ориентир: width 720, radius 16, inset 24/16. Ограниченная высота и отдельная прокрутка результатов; шапка и commit zone не накрывают content. Тонкая линия под поиском появляется при реальной прокрутке. На narrow dialog почти полноэкранный; при очень низкой высоте весь dialog прокручивается, чтобы не зажать список между огромными fixed-зонами. Long-text/native zoom всё равно проверяются отдельно.

## F-01. Ошибка и неизвестный итог — разные состояния

В laboratory selector можно выбрать success, catalog error, write error, lost response, revoked access. Все исходы и задержка 650 ms — явная **локальная симуляция**. Не переносить таймер как минимальное время операции в production.

- Catalog error не изображается как пустой аккаунт. Retry восстанавливает каталог без очистки query/selection.
- Write error сохраняет выбранное. Пользователь повторяет действие явно; в демо повтор успешен, не обещать это в реальной сети.
- Lost response не означает failure. Target фиксируется, изменения выбора временно заблокированы. «Проверить подключение» сверяет simulated binding без повторной mutation. В реальном коде нужны чтение актуальных bindings и поддерживаемые version/idempotency guarantees.
- Revoked access блокирует commit исходного target. Другая доступная запись остаётся выбираемой; никакой обход permission checks.
- Pending блокирует double submit, сохраняет captured target. «Закрыть окно» закрывает представление, а не обещает отмену. Результат после закрытия отражается у источника, не крадёт focus.
- Success показывается один раз у связанного источника, с отдельным уточнением про неизменившиеся права агента.

Демонстрация неизвестного итога охватывает один сценарий: запись завершилась, ответ потерян. Reconciliation с отсутствующей/конфликтующей записью, offline и повторными сбоями остаётся production-тестом, не считается покрытым этой симуляцией.
