# Цвет и состояния

[Индекс](README.md) · контракт 0.2 · направление подтверждено текущим запросом владельца проекта.

## 1. Три независимых слоя

**Рабочий UI:** нейтральные поверхности, текст, borders, hover, focus и selected. Не вводить синий или фиолетовый action accent — ни на кнопках, ни на tabs, links, switch, checkbox, progress control или GitHub action.

**Идентичность:** существующий набор flood blobs сохраняет собственные цвета и формы, включая синий/фиолетовый внутри asset. Запрет синего chrome не является требованием перекрасить синий блоб. Не сводить весь набор к одному градиенту и не генерировать замену реальным assets через CSS. Provider logo может иметь исходный цвет, но не окрашивает соседний control.

**Состояние:** Warning/Attention, Danger/Error, Success используют семантические ink/surface. Цвет подтверждает текст/иконку, не заменяет их. Нормальная активность, текущая вкладка и подключённый provider не получают цвет автоматически.

В forced-colors сохраняется пользовательская system palette, даже если Highlight синий. Не выключать её через forced-color-adjust:none ради бренда.

## 2. Матрица controls

| Состояние | Монохромный сигнал | Что нельзя |
| --- | --- | --- |
| Rest | Ясный label, роль поверхности | Обводить все кнопки одинаково |
| Hover | Небольшая смена neutral surface | Считать hover единственным признаком кликабельности |
| Pressed | Более определённый neutral tone | Менять layout и border width |
| Selected/current | Neutral surface + контрастная отметка/индикатор, ARIA state | Слабый серый wash как единственное доказательство выбора |
| Focus-visible | Независимый контрастный нейтральный outline | Убирать focus ради тонкого edge; заменять его бликом |
| Disabled | Нейтральный muted state и понятная причина рядом, когда нужна | Делать важное объяснение нечитаемым |
| Pending | Сохранять размеры/label, показать состояние работы | Показывать зелёный success до подтверждения |
| Invalid | Danger-текст/иконка/локальная граница поля; focus остаётся независимым | Делать красной всю форму или стирать draft |

Primary — ink fill + on-ink text. В dark label может быть тёмным на светлой кнопке. Primary сохраняет приоритет на hover; secondary не становится ещё выразительнее. Links в тексте нейтральные, но различимы подчёркиванием/формой и focus. Native controls требуют нейтрального accent-color и проверки реального OS/WebView результата.

Глобальный синий browser selection не использовать как собственный дизайнерский акцент: задать semantic selection roles и проверить читаемость выделенного текста. System-selected high-contrast mode не переопределять.

## 3. Розово-красный Danger сохраняем

На baseline `933df40` в `src/styles.css`:

| Роль | Light | Dark |
| --- | --- | --- |
| Существующий danger ink | #d92f55 | #ff607d |
| Существующая danger surface | #fff0f3 | #32171f |

Оттенок нравится владельцу проекта и остаётся частью языка Flood. Не заменять его на чистый #ff0000, бордовый или generic destructive palette ради сходства с библиотекой.

**Но один цвет не обязан одновременно быть текстом, заливкой и иконкой.** Для непрозрачной пары #d92f55 / #fff0f3 расчёт даёт около **4.236:1**: это ниже 4.5:1 для обычного текста. На белом #d92f55 даёт около **4.679:1**. Это аудит пары tokens, а не утверждение, что все реальные error labels приложения уже используют именно эту пару.

Предложенное уточнение для пилота:

- `danger-mark`: сохранить #d92f55 light / #ff607d dark для семантической метки при достаточном контрасте.
- `danger-text`: #c7274e light на #fff0f3 даёт около **4.965:1**; dark #ff607d на #32171f — **5.651:1**.
- `danger-solid`: сохранить исходное семейство. Для light заливки #d92f55 белый текст даёт 4.679:1; для dark заливки #ff607d текст #151513 — **6.287:1**. Не ставить белый label на яркий dark-theme pink без измерения.

Измерения воспроизводятся в [check-materials.mjs](recipes/check-materials.mjs). Значения округлены только для отчёта; тест сравнивает полную точность. Прозрачность, overlays, hover и другая подложка требуют отдельного пересчёта. Production tokens в этом изменении не перекрашиваются.

Требования к тексту: [WCAG Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). Не ослаблять contrast rule ради сохранения одного hex: сохраняем характер палитры через разные роли.

## 4. Где нужен Danger

Активная ошибка, потерянный доступ, invalid field, важное предупреждение об удалении и окончательное destructive confirmation — допустимые места для розово-красной семантики. Ранее написанное «danger только в подтверждении» относится к акценту опасной кнопки, а не запрещает красный текст настоящей ошибки.

Обычный entry «Удалить…» может быть нейтральным до раскрытия последствий; последнее подтверждение локально использует Danger. Цвет не заменяет описание объекта, масштаба и возможности восстановления. Не делать весь modal красным.

Error остаётся видимым, пока мешает работе. Не прятать его через две секунды в toast, если от пользователя требуется исправление. После восстановления убрать устаревший красный статус, сохранив историю в подходящем месте.

## 5. Warning и Success

Warning означает риск, неполноту или необходимость внимания, а не любую второстепенную подсказку. Текст объясняет, что произойдёт и какое действие доступно. Neutral informational notice не обязан быть жёлтым. Не добавлять синий Info как четвёртый акцент.

Success означает подтверждённый результат операции. Для обычного сохранения часто достаточно спокойного текста «Сохранено», без зелёной карточки. У результата агента различать «Готово к проверке» и «Применено»: первое не свидетельствует, что изменения уже приняты.

Семантическая поверхность цельная: без чёрного count внутри цветной карточки, разноцветных вложенных rows и окрашивания всех соседних controls. Иногда достаточно одной иконки + текста; tinted fill не обязателен.

## 6. Темы и бренд

Светлая тема — белая/нейтральная, тёмная — графитовая; обе используют ту же структуру, не два разных продукта. Тёплый нейтральный оттенок текущего Flood допустим; намеренный голубой cast у chrome — нет.

Не получать dark theme инверсией цветов. Для каждой роли явно проверить foreground/background. Не использовать одно и то же alpha для разных подложек как доказательство равной воспринимаемой плотности. Плавная смена цвета не должна создавать задержку появления нового состояния.

Набор блобсов — идентичности и редкие выразительные моменты. Не назначать зелёный shape «успеху», красный «ошибке», синий «выбранному проекту», если это смешивает identity и state. Agent name и label «Агент» читаются отдельно; run state имеет собственную подпись. Не размещать длинный рабочий текст поверх блика или прозрачной области blob.

## 7. Что проверяет агент

Найти `accent`, literal blue, native accent-color, focus/selected/checked styles и проверить их семантику, а не удалить все синие пиксели из assets. Просмотреть обе темы с error, selected и focus одновременно. Для текста на статусной заливке измерить реальную пару, не отдельный token на белом.

Результат проверки: какие роли использованы, какие opaque/composited пары измерены, какие states осмотрены, что не проверено. Автоматическая проверка 74 пар в specimen не является аудитом всех экранов Flood.
